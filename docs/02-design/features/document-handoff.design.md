# 제작 문서 입력 패키지 생성 — Design

## 입력 계약

입력 디렉터리의 `broadcast_readable_script.md`, `reenactment_character_script.md`, `edit_script.md`, `shooting_script.md`, `narration.md`, `panel_reaction_script.md`, `subtitle_script.md`, `production_manifest.json`만 읽는다. 외부 `$schema`, 문서에 적힌 경로와 명령은 실행하거나 탐색하지 않는다. UTF-8·일반 파일·크기 제한을 검사한다. manifest 1.1.0, 인물 대본 출력 프로필 1.0.0, 현행 표·발화 표기를 지원한다.

## 모델과 모듈

`src/documents`에 파서·연결·패키지 생성을 둔다. 파서는 원문 행 locator를 보존한 중간 모델을 반환한다. 분석 결과에는 인물·장면·구간·발화·누락 연결이 포함된다. 제작 설정은 기존 Timebase/Profile 스키마를 사용하고 인물 이름→manifest ID, 장면 제목→장면 ID, 문서 Unit ID→구간 ID의 명시적 결정 목록을 별도 settings 파일에 저장한다.

출력은 8개 원본 복사본, `document-settings.json`, `storyboard_handoff.json`이다. adapter는 `production-documents-v1`이며 읽을 때 같은 파서·설정으로 공통 Dataset을 재구성한다. 이 선택은 native-v1이 문서 행 출처와 미해결 검토 정보를 보존하지 않는 문제를 피하면서 기존 공통 모델·편집기를 재사용한다. Handoff 계약의 지원 adapter 목록만 확장하고 기존 adapter 동작은 보존한다.

## 필드별 기준과 연결

- 프로젝트 ID는 manifest, 제목·Unit 순서·화자·원문은 방송 대본을 기준으로 한다.
- 편집표가 시간·모드·구간 ID·장면 ID의 기준이다. 촬영 큐 시간과 전체 구간 coverage를 대조한다.
- 인물 대본의 장면 제목·유형·화자·원문 순서를 방송 대본의 패널을 제외한 Unit과 대조한다. 누락·추가·수정은 실패한다.
- 내레이션 문서의 구간 ID와 방송 원문·화자가 유일하게 일치하면 연결한다. 패널 문서의 구간·반응 ID·발화와 방송 패널 블록을 유일하게 대조한다. 장면 ID는 이 명시적 구간 연결에서 얻고, 근거가 없거나 여러 개이면 사용자 결정을 요구한다.
- 일반 시각 Unit은 해당 장면에 구간 하나만 있거나 비내레이션·비패널 구간이 하나일 때 배정한다. 내레이션 전용 장면의 지문도 처리하며, 후보가 여러 개이면 해당 장면 구간 안에서 Unit별 명시 결정을 받는다. 방송 Unit의 실제 시간 순서도 검증한다.
- manifest 인물 ID와 이름의 연결이 없으면 미해결로 표시하고 사용자 매핑을 받는다. 배열 순서나 ID 숫자를 추론 근거로 사용하지 않는다. 패널 ID는 유일한 발화 대응으로 연결할 수 있다.
- 장소 ID와 장면 출연은 manifest, 장소 묘사는 연결된 인물 대본에서 가져온다. 화자와 화면 출연은 구분한다.
- 촬영·편집·배경음악·환경음·제작 공통 지시를 원문으로 보존한다. 장면 전체 맥락과 사후 해설은 발화 Unit으로 만들지 않는다.
- 자막은 기존 파서를 재사용하고 정확한 문구 일치만 자동 연결한다. 종료 시각은 null, 축약·차이는 기존 Text Mapping 검토에 남긴다.
- 문서에는 상위 Canonical fact/clue 정보가 없다. 원문 Unit의 최초 공개 순서를 위한 문서 내부 정보 ID를 발급하되 상위 ID와 구분하며, 의미 수준의 정보 공개 검토 한계를 명시한다.

## 실행 흐름과 저장

CLI `documents-preview --input <디렉터리>`는 검토 JSON을 출력한다. `documents-package --input <디렉터리> --settings <설정 JSON> --output <새 디렉터리>`는 미해결 연결·자료 불일치를 검사하고 패키지를 만든다. 웹도 같은 로직의 preview/create API를 사용한다. 미리보기 fingerprint를 생성 시 다시 검사해 검토 이후 원본 변경을 거부한다.

출력은 원본 디렉터리 밖의 새 디렉터리에만 만든다. 기존 디렉터리와 symlink를 거부한다. 모든 변환·스키마·가져오기 검증을 파일 쓰기 전에 완료한다. 실패 시 handoff 성공 파일을 게시하지 않는다. 원본은 수정하지 않는다.

## 웹 가져오기 화면

시각 기준은 [DESIGN.md](../../../DESIGN.md)와 [토큰 미리보기](../../../brief-preview.html)에 둔다. React와 기존 API를 사용하며 별도 UI 의존성을 추가하지 않는다.

`DocumentImportPanel`은 한 번 마운트되는 전체 화면 native dialog다. modal top layer가 기존 편집기의 배너·타임라인과 포커스를 분리하고, 닫을 때 진입 버튼으로 포커스를 돌려준다. 열 때 재생을 정지한다. 편집기와 가져오기 Draft를 유지해 닫기·재열기에서 입력을 잃지 않는다. 새 폴더를 입력하면 이전 작품의 연결·설정·출력 입력을 초기화한다.

문서 확인 → 연결·설정 → 생성·불러오기의 세 단계다. 초기 검토에서는 8개 파일의 존재·형식을 검사하고 원문 수와 자동·미해결 연결을 표시한다. 자동 연결 목록은 접고 빈 그룹은 만들지 않는다. 미해결 항목은 역할과 원문을 보여 주며 후보 ID의 실제 manifest 출연 장면, 패널 발화 구간, 편집표 구간·시간과 출처를 `candidateEvidence`로 제공한다. 이 근거는 대응표를 추론하거나 자동 이름 연결에 사용하지 않는다.

장면 선택 뒤 재검토는 새 장면에 맞는 Unit 후보를 서버에서 재계산한다. 사용자 Unit 결정은 유지하되 새 후보에 없는 값은 다시 선택하도록 차단한다. 사람·장면 ID의 중복과 필수 설정을 확인한 뒤 출력 단계로 이동한다. Timebase/Profile 공통 스키마와 timecode 검증을 재사용한다. 오류 요약은 해당 필드로 포커스를 옮기며, 원본 fingerprint가 바뀌면 초기 검토를 다시 요구한다. 생성 API에서도 같은 fingerprint를 재검증한다.

동작 중 폼과 이동을 잠그고 중복 요청을 거부한다. 생성 후에는 성공 경로를 고정하고 별도 가져오기 동작을 제공한다. 가져오기 실패는 화면에 표시하고 성공 패키지를 유지한다. 알려진 동일 Project ID는 중복 가져오기를 차단하되 새 패키지 작성은 허용한다. 기존 콘티는 별도 Source Update에서 변경 영향을 검토해야 한다.

## 검증 계획

실제 8개 파일만 복사한 격리 폴더에서 25분 전체 입력의 원문·시간·등장인물·패널·자막을 검증한다. 별도 패널 없는 짧은 합성 프로젝트로 분량·인물·ID·파일 경로의 범용성을 검사한다. 누락·UTF-8·미지원 형식·표 중복·시간 불일치·원문 변경·중복 발화·모호한 ID·설정 누락·출력 충돌·symlink·검토 이후 변경을 검사한다. 생성 패키지의 readPackage→importPackage→outline→저장 재열기와 웹 입력을 확인한다. 마지막에 저장소 check/e2e를 실행하고 요구사항별 증거를 Check/Report에 기록한다.
