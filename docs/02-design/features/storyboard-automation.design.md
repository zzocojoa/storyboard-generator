# 검토용 콘티 자동 제작

## 기본 콘티와 선택 음성의 완료 경계

신규 실행 설정 `audioProduction=instructions-only`는 콘티만 제작하며 설치 음성 조회·배정·합성을 요구하지 않는다. `guide-voice`는 선택한 발화의 음성 합성과 실측 배치를 추가한다. 이전 실행의 필드 부재는 기존 음성 계약을 의미하며 기존 설정 해시와 원본 파일은 유지한다. 기본 실행 완료 이후에도 개별 음성 요청은 사용할 수 있다.

기본 Final은 컷·그림·글자·음향 지시 검토와 원문·시간·정보 공개를 검사한다. 음원 없는 발화 시각은 `proposed`이고, 음성 전용 `audio-only` Link가 있으면 원본 구간 안의 시작은 그 최초 확정 Anchor와 일치해야 한다. 같은 Unit을 그림과 발화에 함께 쓰면 컷에는 중복 없는 직접 시각 Link를 두고 Audio Cue에서 독립 시각을 지정한다. 음성 전용 Anchor가 없는 이 경우에는 확정된 직접 시각 최초 공개 이후의 Cue 시작을 계획 근거로 사용한다. `context-only`·미확정·누락 Source나 Cue보다 늦은 시각 공개는 근거가 아니며, 이미 명시한 음성 전용 Anchor의 불일치를 직접 시각 Link로 우회하지 않는다. 같은 원본 구간 안의 명시적인 계획 시점은 `planned-audio` Gate 근거가 되며 원래 하한과 더 늦은 Unit-order 근거를 앞당길 수 없다. J-cut은 기존 인접 구간 배치와 정보 공개 검사를 따르며 Gate를 앞당기는 계획 근거로 사용하지 않는다. 실제 재생은 측정된 파일·길이·연결 검사를 계속 사용한다. 콘티 전용 실행은 미완성 음성 설정도 사용하지 않고 보존하며 가이드 음성을 선택할 때 엄격하게 검사한다.

Final Report는 콘티 차단 `issues`와 선택 재생 점검 `optionalAudioIssues`를 분리한다. PDF·CSV는 원문 대사·효과음·음악 지시를 포함하고 계획 시각을 실측으로 표시하지 않는다. 사용자 검토와 승인은 그대로 필요하다. 선택 음원 자체의 손상·모순을 성공으로 표시하지 않는다.

## 목표와 완료 조건

사용자가 승인한 기본 범위는 설정·원문 배치·컷·그림·시간·대사·음향 지시를 자동으로 만든 뒤 같은 화면에서 검토하고 선택 재생성하여 최종 출력하는 흐름이다. [설정 분석](../../03-analysis/storyboard-automation-settings.analysis.md)의 P0/P1을 구현한다. 고급 믹싱·외부 영상 편집기·완성 영상 업로드는 범위를 확장하지 않는다.

| 요구사항 | 구현·검증 증거 |
|---|---|
| A01 버튼에서 실제 Codex 실행 | 설치본 프로토콜·로그인 확인, 실제 구조화 응답·내장 이미지 생성, API 키 없이 결과 전달 |
| A02 미정 입력 자동 계획 | mapping-required 입력에서 시작, 원문 ID·본문·확정 시간표 보존, Source·Text·Audio 후보를 함께 검사 |
| A03 제작 설정·시각 기준 | 기존 사용자 설정 우선, 제작 제안의 근거·입력 결속, 필요한 인물/공간/소품·연속성 기준 연결 |
| A04 대사 시각·선택 음성 | 기본은 원문과 명시 Source Anchor에 맞춘 콘티 시각 계획. 가이드 음성 선택 시에만 staging 합성·WAV 검사 후 실측 배치. 고정 구간 길이 보존 |
| A05 그림 자동 생성 | 해당 Frame 시점의 직접 근거·참조만 전달, 실제 이미지 검사·신규 Asset 반영, 파생 Frame 포함한 작업 수 제한 |
| A06 실행 관리 | 프로젝트별 실행 상태·유한한 보정/재시도·취소·재개·진척·예외. 브라우저와 실행 수명 분리 |
| A07 사용자 검토 | 무결성 확인한 미승인 미디어의 검토 화면·재생. 기술 검사와 사용자 승인 분리. 필요한 결과만 재생성 |
| A08 기존 편집·원본 보존 | 시작 Snapshot·revision·설정/참조 해시 결속, 오래된 결과 거부, 잠금·사용자 수정·Asset/Record 보존 |
| A09 출력 | 화면비·자막 조판·긴 내용의 표현을 검토하고 JSON·PDF·CSV 출력. 현행 Final 판정 유지 |
| A10 범용성 | 서로 다른 스토리·길이·선택 요소·공유 원본 ID에 같은 실행. 미정 입력부터 실제 실행까지 검증 |

전체 완료 판정은 위 요구별 실제 증거를 검사한다. 한 구간이나 연결부 테스트만 통과한 것을 전체 자동화 완료라고 보고하지 않는다.

## 실행 경계

기존 문서 검토와 전체 제작은 서로 다른 실행이다. 문서 검토는 선택 문서의 읽기 전용 구조화 응답만 받는다. 제작도 모델에게 ProjectStore 파일 수정 권한을 주지 않고 검증된 후보·미디어 결과를 받은 뒤 서버가 기존 트랜잭션으로 반영한다.

- 공통 stdio JSON-RPC 연결은 요청 대응, 바이트 제한, 시간 초과, 종료·취소·오류 정산을 담당한다.
- 구조화 계획 엔진은 선택 스냅샷과 Schema만 보낸다. 셸·외부 MCP·앱·웹·추가 파일 탐색을 허용하지 않는다.
- 이미지 엔진은 실제 지원 능력을 검증하고 생성 이벤트의 결과만 받는다. 출력 경로가 반환될 경우 허용된 실행 영역·정규 파일·크기·해시를 검사하고 등록한다.
- 가이드 음성은 고정 명령 인수로 로컬 음성을 실행한다. 원문 파일을 사용하고 셸 문자열로 대사를 전달하지 않는다.
- 기술 오류는 제한된 재시도 또는 후보 보정으로 처리한다. 정상 그림을 취향 때문에 반복 생성하는 작업은 사용자의 선택 후 실행한다.
- 모델이 요청한 임의 도구 실행·권한 확장·원본 변경은 거부한다. 실행 능력이 없으면 해당 기능을 사용 가능하다고 표시하지 않는다.

App Server 세션의 임시 작업 폴더는 생성 시 실제 장치·inode를 기록한다. 자식 프로세스 종료 뒤 정리 직전에 동일 폴더·정규 경로인지 다시 확인하며, 폴더 교체·심볼릭 링크·경로 소실은 `CODEX_WORKSPACE_CHANGED`로 정리를 중단한다. 다른 위치를 찾아 대신 지우거나 같은 경로의 새 파일을 삭제하지 않는다. 정상 종료·취소·초기화 실패는 소유권이 유지된 세션 폴더만 정리한다. 이는 협력하는 로컬 실행의 정리 계약이며 임의 외부 프로세스와 삭제 작업 자체를 원자적으로 동기화한다는 보장은 아니다.

Codex 제한 시간 오류는 현재 모델·추론 수준, 경과 시간, 수신 바이트, 마지막 RPC/이벤트 종류와 시각, 대기 RPC 개수, 자식 종료 여부를 포함한다. 이 값은 실행 연결에서 관찰한 메타데이터이며 프롬프트·원문·모델 사고 본문은 넣지 않는다. 연결 준비와 응답 생성 중 제한 초과를 구별하는 근거로 사용하며, 이벤트 수신 자체를 생성 완료로 판정하지 않는다. RPC 제한과 전체 실행 예산, 취소·자식 종료 계약은 이 진단 때문에 변경하지 않는다.

설치된 프로토콜 Snapshot은 `.local/validation/automation-runtime/protocol`에서 확인한다. 런타임 연결 문법은 [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)와 설치본을 대조한다. `imageGeneration` 이벤트가 타입에 존재하는 것만으로 현재 계정의 실제 생성 성공을 증명하지 않는다.

## 후보 계획과 적용

원본 Dataset은 변경하지 않는다. 자동 계획은 `sourceLinks` 용도·시각, Text 관계·정보성·표시, 발화 배치, Profile·연출·Frame 계획의 별도 후보이다. 확정 원문과 제작 제안의 출처를 보존한다. 미정 입력을 모두 confirmed로 바꾸어 기존 Proposal 검사를 통과시키는 경로를 만들지 않는다.

staging에서 측정한 음성 길이와 후보 Anchor/글자 시각으로 전체 후보를 검증한다. 합성 전부터 기존 Gate를 통과하도록 요구하지 않되 Project 반영 전에는 원문·순서·시간·노출 정책을 만족해야 한다. 후보 적용은 같은 revision에 검사하며 모델 호출 중 Project Lock을 보유하지 않는다.

자동화의 구조적 확정과 사람의 검토는 별도 상태다. 자동 계획은 생성 입력으로 사용할 수 있지만 Shot Approval·Frame Accept·Text Confirm 등 사용자 승인 결과를 위조하지 않는다. 검토 전용 출력은 그 상태를 명확히 표시하며 Final 경로의 규칙을 완화하지 않는다.

현재 구간 후보는 전체 Project hash·revision과 명시한 교체 Shot ID 집합에 결속한다. 모델은 원문 본문을 반환하지 않고 Source ID·용도·범위, 미해결 Mapping과 독립 글자 정보성, 파생 글자 시각, 기존 Audio Cue의 시각, 연출·Frame을 제안한다. 서버는 원문에서 글자를 도출하고 실제 WAV를 다시 읽어 해시·길이·형식을 대조한 뒤 같은 후보에서 Gate·Coverage·모든 채널의 최초 공개 순서·전환을 검사한다. 기존 확정 Mapping·Text·측정 Audio는 자동 변경하지 않는다. 교체 대상 밖의 기존 미해결 검토는 유지하되 새로 생긴 영향은 차단한다. 효과음·음악은 원문 지시와 계획 시각으로 출력한다. 실제 파일 부재는 선택 재생 상태에만 남기며 기본 콘티 Final을 차단하지 않는다.

계획과 음성의 Record는 구분하여 원문 해시·모델 Turn·실제 음성·선택 설정·검증한 모델 결과를 남긴다. 원문 연결 확정은 이 검증된 제작 제안의 구조 상태이며 사람의 연출·이미지·자막 승인을 뜻하지 않는다. 구간 후보 함수는 파일을 쓰지 않고 Project와 AssetWrite를 반환한다. 실행 관리자는 ProjectStore의 기존 잠금 아래에서 Basis를 다시 확인하고 한 revision으로 적용해야 한다. 실행별 적용 Intent와 중단 정산을 연결하기 전에는 브라우저 버튼에 직접 노출하지 않는다.

## 제작 기준과 참조 버전

Project 1.11.0의 `productionPlan`은 원본 Dataset과 분리한 제작 제안이다. Resource는 인물·장소·소품의 설명, 원문 출처·Unit ID, 제안 이유, Generation ID, 정확한 참조 Asset ID를 가진다. Segment 계획은 사용할 Resource와 화면 장소·연속성 그룹·시작/종료 상태를 연결한다. 원문에 없는 촬영 세트는 별도 제작 장소로 만들며 Dataset의 장소나 사건을 바꾸지 않는다. 사용자가 지정한 방식·그림체·화면비를 자동 덮지 않는다.

기준 이미지 후보는 실제 모델·Turn·이미지 바이트를 결속하고 전체 디코딩·해시·비율을 검사한 후 신규 Asset·Record를 추가한다. 구간은 선택한 버전을 사용하며 전역 최신 의상으로 교체하지 않는다. 동일 인물의 앞선 외형 기준만 얼굴 참조로 사용하고 미래 상태의 기준을 앞 구간에 주지 않는다. 원본 장소 ID가 같은 공간 변형은 앞서 사용한 기본 공간 이미지도 첨부하여 창문·출입구·벽·고정 가구의 형태와 배치를 유지한다. 기본 공간 후보는 사건 상태 Unit이 없는 기준으로 한정하며, 원본 ID가 없는 독립 세트·소품을 이름 유사성으로 연결하지 않는다. 참조 실제 바이트·해시와 선택 목록을 생성 기록에 보존한다. 기준 재생성 시 관련 소품·연속성 참조도 새 버전으로 연결하고 해당 컷/프레임을 검토 상태로 전환한다. 확정·잠금 컷이 사용하는 기준은 자동 교체하지 않는다.

`POST /api/projects/:projectId/automation/reference-retakes`는 선택 Resource·현재 revision·실행 한도를 받아 `reference-retake` 목적의 한 작업만 실행한다. 시작 당시 설명·기존 Asset·사용 구간·프로필·연속성 참조를 해시로 결속하고 시작·재개·실행에서 다시 검사한다. 이미지 시도·시간·바이트 한도, Worker, 후보 보존·Apply·정산은 일반 자동 제작과 공유한다. 기존 이미지 파일도 실제 검사한다. 다른 제작 계획·컷 그림·발화 생성으로 확장하지 않는다. 제작 설정의 기준 검토 화면에서 선택한 현재 이미지와 그 Resource의 보존된 이전 버전만 비교하며, 전체 목록의 같은 원본 ID를 이전 버전으로 오인하지 않는다. 조회·재열기는 새 생성을 시작하지 않는다. 선택 기준의 교체 이후 다른 변형이나 컷 그림의 재생성이 필요한지는 사용자가 검토하며 이 요청으로 자동 승인하지 않는다.

선택 재생성의 `correctionNote`는 공백을 제외한 1~4,000자의 시각 수정 요청이다. 지정하면 수정 대상의 현재 이미지도 기존 연속성 참조와 함께 첨부하고 서로 다른 역할로 표시한다. 요청·참조 버전은 Intent 해시·Basis·새 Generation Record에 결속하며 수정 내용이 바뀐 요청은 재개하지 않는다. 원문·Resource 설명·사건·정보 공개 조건을 변경하는 권한이 아니며 이전 자산·기록과 사람 승인 상태를 보존한다. 필드가 없는 기존 실행은 이전 입력 계약을 유지한다. 웹은 선택 기준의 수정 요청을 보내고 저장된 실행 문구를 재열기 후 표시한다.

미전송 수정 요청·앞선 소품 선택·동일성 근거는 Project와 Resource별 브라우저 초안으로 보관한다. 대상을 전환하거나 새로고침한 뒤 같은 기준을 선택하면 복원하며 생성·승인을 실행하지 않는다. 작성 당시 revision과 현재 기준이 다르거나 다른 화면의 입력이 충돌하면 비교·선택 전까지 재생성을 차단한다. 현재 사용할 수 없는 앞선 기준은 ID와 문구를 보존해 다시 선택하도록 표시한다. 사라지거나 사용되지 않는 Resource의 입력도 미저장 편집 기록에서 원래 값으로 확인할 수 있다.

Project 1.24의 소품 `propContinuity`는 앞선 Resource ID와 동일한 물건으로 판단한 근거를 저장한다. 제작 계획 결과 1.1은 새 key 또는 기존 Resource ID로 이를 명시하며 무관한 자원에는 null을 반환한다. 이름·나열 순서로 연결하지 않는다. 다른 종류·없는 대상·자기 참조·순환·뒤 구간 또는 같은 구간의 나중 상태를 거부한다. 기준 그림은 이 연결의 정확한 이전 Asset 바이트를 첨부하고 판형·재질·색상·표 구획을 유지하며 현재 설명의 상태만 적용한다. 생성 대기열은 선택 범위 안의 원형을 먼저 준비하며 범위 밖의 누락 그림을 조용히 생성하지 않는다.

기준 재생성의 선택 입력에도 `propContinuity`를 제공할 수 있다. 선택·근거·실제 이전 이미지 버전을 시작 Intent와 생성 Basis에 결속하고, 새 이미지가 원자 적용될 때만 선택 Resource에 함께 저장한다. 실패·취소·오래된 결과는 기존 연결과 파일을 바꾸지 않는다. 제작 설정의 소품 검토에서 앞선 기준 미리보기와 동일성 근거 입력을 제공한다. 기존 변형·컷 그림·사람 승인을 일괄 재생성하거나 확정하지 않는다. 원본 변경 영향은 연결된 원형의 근거까지 추적한다. 1.23 저장본은 버전만 메모리에서 이관하며 연결을 추측하거나 과거 Record를 재작성하지 않는다.

Source Update는 실제 변경 Unit·인물·장소에 의존하는 Segment의 기준 연결만 해제하여 재계획을 요구한다. 과거 Resource·Asset·Record는 감사용으로 보존한다. 현재 어느 구간에도 쓰이지 않는 과거 기준에는 이미지 생성을 요청할 수 없다. 기존 1.10 저장본은 읽을 때만 `productionPlan: null`을 추가한다. 인식하지 못하는 과거 비어 있지 않은 계획을 조용히 삭제하지 않는다.

## 현재 프레임의 그림 생성

`frame-image.ts`는 전체 Project 해시·revision·Frame ID·선택 기준 Asset 버전을 결속한다. 중앙 Source/Gate 검사 뒤 현재 시각의 직접 원문만 전달하고, 컷 전체 지문·종료 상태·음성 전용 화자·미래 원문·정확한 화면 문구를 제외한다. 파생 Frame의 설명이 비어 있어도 활성 원문과 카메라·기준 이미지로 생성한다. 화면 글자는 별도 트랙에서 합성한다.

시각 기준의 실제 바이트·해시·종류를 검사하고 같은 구간에서도 근거 Unit 공개 이전의 상태 기준을 거부한다. 기본 외형·공간은 원본 인물/장소 근거로 연결하며 사건 상태의 Unit 근거와 구별한다. 현재 지원 입력은 한 프레임당 원본 참조 20개·합계 20MiB이며 모델 첨부는 최대 5개다. 5개 이하는 원본 바이트 그대로 전달하고 6~20개는 순서를 유지해 번호가 있는 참조 보드로 묶는다. 보드당 최대 4개, 원본당 1024×1024 영역 안에 전체 이미지를 비율 보존·자르기 없이 배치하며 번호는 영역 밖에 둔다. 원본 자산은 재작성하지 않는다. 준비한 첨부 합계에도 별도 20MiB 한도를 적용한다. 원본 해시·순서·설명과 첨부 해시·크기·위치의 version 1.0.0 기록을 Generation Record의 prompt에 보존하며 적용 시 원본 선택과 일치하는지 검사한다. 보드가 필요한 생성에 기록이 없거나 순서·배치가 다르면 적용하지 않는다. 한도를 넘으면 참조를 조용히 누락하지 않는다. 실제 PNG 디코딩·비율·모델·Turn·입력을 검증한 새 Asset/Record만 추가하고 Frame을 pending으로 저장한다. 확정 이미지와 잠금 컷은 자동 교체하지 않는다.

## 실행 상태와 적용 복구

`AutomationRunStore`는 시작 Project Snapshot, 선택 구간, 모델·음성·한도와 생성 Build를 결속한다. 이후 이벤트는 이전 해시·순번을 가진 파일로 추가한다. HEAD보다 앞서 게시된 연속 이벤트만 복구하며 이력 공백·HEAD 해시 불일치·symlink·같은 순번의 경쟁은 명시적으로 거부한다. 같은 프로젝트의 미종료 Run은 하나이며, 작업 ID와 의존 관계는 등록 후 보존한다. 제작 계획 배치·기준 이미지·구간 계획·프레임 이미지 작업을 구별한다.

실행 reducer는 생성 시도·이미지 시도·활성 시간·준비 파일 누적량을 유지한다. 일시 중지와 재개로 한도를 초기화하지 않는다. 중단 직전에 보존한 결과는 새 모델 호출 없이 준비 상태로 복구할 수 있다. 실행 중 취소는 호출 중단과 적용 정산이 선행되어야 한다. 실제 Commit 영수증 없이 applying을 완료로 바꾸지 않으며 모든 작업이 반영되어야 review-ready가 된다. 이 상태는 사용자 승인이나 Final Ready가 아니다.

`AutomationApplicationStore`는 각 시도 ID에 원본·후보 Project, 새 미디어, Record 해시, Run·Job·설정 해시를 원본 밖에 보존한다. 영속 Intent를 먼저 공개하고 기존 ProjectStore의 Lock 안에서 전체 Basis와 revision을 다시 검사한 뒤 원자 반영한다. 실제 도입 Version, 직전 Version, append-only Record와 신규 Asset을 대조해 최초 적용 revision을 영수증에 기록한다. Commit 직후 중단되어 임시 미디어가 사라졌거나 후속 사용자 편집이 생겨도 실제 최초 Version으로 정산하며 현재 콘티를 되돌리지 않는다. 증거가 없거나 모순되면 성공으로 만들지 않는다.

저장 형식이 바뀌어도 과거 Run·Application·영수증의 해시는 재작성하지 않는다. 시작 Snapshot은 원래 JSON의 해시를 먼저 검사한 뒤 메모리에서 이관한다. 적용 정산은 실제 Version 파일과 정의된 순방향 이관으로만 얻은 해시를 대조한다. 현재 모델의 버전을 과거 번호로 바꾸어 증거를 추측하지 않는다. 이전 Build의 미반영 후보는 새 코드로 적용하지 않고 기존 실행 취소·새 실행을 요구하며, 이미 게시된 결과의 정산은 Build 변경보다 먼저 수행한다. ProjectStore는 이전 Current의 실제 바이트를 Journal·CAS·rollback 근거로 사용하고 기존 Version을 보존한다.

`job-graph.ts`와 `run-executor.ts`는 제작 기준 배치 → 기준 이미지 → 컷·시각 계획 → 파생 Frame 그림을 시간순으로 실행한다. 가이드 음성 선택 시에는 컷 계획 전에 실측 음성을 준비한다. 수동·기존 모델 컷에는 별도 `repair` 작업을 우선한다. Project 전체 해시·revision과 현재 미정 Link의 Shot ID·배열 위치·Unit ID, 재검증할 Audio Cue ID와 미등록 발화 Cue ID를 결속한다. 모델은 대상 링크의 용도·시각과 명시된 미등록 발화의 배치만 반환하며 확정 usage는 보존한다. 기존 컷 ID·길이·연출·그림·텍스트·기존 음원 배치는 유지하고 등록된 WAV는 실측 상태로 복원한다. Source의 새 공개 시점에 필요한 키 프레임은 예산 안에서 추가한다. 모든 변경을 원자 후보에서 검사하고 신규/확대된 다른 출력 충돌도 차단한다. 승인·잠금 컷과 accepted 그림이 있는 컷은 보완 범위에서 제외하며 공유 음원도 보호한다. 가이드 음성을 선택한 실행은 미등록 대사·내레이션·패널 발화를 모델 호출 전에 한 번 준비한다. 기본 콘티 실행은 합성을 호출하지 않고 원문·호흡·연출에 맞춘 계획 시각을 저장한다. 새 음성의 실제 길이를 현재 Cue의 시작/종료 범위 안에서 배치하고 timingRelation을 보존한다. 효과음·음악·화면 글자를 낭독하거나 발화를 늘이기·자르기·반복으로 맞추지 않는다. 보호 컷의 원문을 공유하거나 시간상 겹치는 발화도 제외한다. 결과 계약 1.1.0은 대상별 audioTimings를 요구하고 1.0.0은 음성 배치 없는 이전 결과로 명시적으로 읽는다. 기존 Record는 재작성하지 않는다. 준비 음성은 실행 캐시에 보존해 보정과 재개 때 재사용하며 실제 WAV·Source Anchor·정보 Gate를 한 후보에서 검증한다. 모델 결과·기존 음원 검사·잔여 Final 검토는 생성 Record에 보존하며 모델 실행 후 파일과 Project를 다시 검사한다. 미정 제작 기준과 빈 그림은 기존 실행 순서로 이어지며 기존 pending 그림은 재생성 표시 없이는 교체하지 않는다. 명시한 rejected Frame은 같은 구간의 다른 accepted Frame 때문에 제외하지 않고, 컷 승인·잠금을 다시 검사해 그 그림만 재생성한다. Worker 전용 Lock을 생성 호출 동안 보유하고 Project Lock은 실제 적용 때만 사용한다. 이벤트 읽기는 최대 8개씩 병렬화하되 전체 해시·순번·상태 전이 검사는 유지한다.

준비/적용 상태는 새 호출 전에 정산하고, 현재 Build·입력 해시와 실제 파일을 검사한다. 전체 잔여 시간의 취소 신호를 모델 보정·음성·그림 호출에 공유한다. 이미지 요청은 최대 출력 바이트를 수용할 예산이 있어야 시작하며 실제 게시 바이트를 누적한다. 일시적 전송 오류는 경고와 유한 재시도 이력으로 남기고 로그인·계약 오류는 원인을 보존한다. 생성 중 사용자 편집을 발견하면 덮어쓰지 않는다.

`AutomationService`는 서버 기동 시 실행을 발견하고 실제 Commit을 정산한 뒤 일시 중지한다. 재개 요청은 저장된 설정·Build·현재 Project 해시를 확인한다. 취소·종료는 Provider 종료를 기다리고 Project Store를 마지막에 닫는다. 취소는 이미 게시한 결과를 보존하고 미게시 후보를 적용하지 않는다. `/api/projects/:projectId/automation` 및 실행별 pause/resume/cancel API를 사용하며 같은 Origin에서만 변경한다. Web은 실행 범위·한도, 작업 진행, 원인과 중단/재개를 표시한다. 결과를 불러오는 명시적 동작으로 편집 내용을 보호하고, 미승인 원본 그림은 실제 자산 무결성 API로 검토한다. Program Monitor와 Final은 기존 안전 출력 경로를 유지한다. 미반영 가이드 음성은 `AutomaticSpeechCache`에 실행·프로젝트·설정/Build·원문·선택 음성과 결속해 보존한다. 전체 파일과 실제 WAV 해시·형식·길이를 확인한 뒤 재사용하며 최초 생성 시각을 Record에 유지한다. 완성된 게시 전/후 파일만 동일 inode로 복구하고 손상·모호한 파일은 보존한 오류로 처리한다. 파일 크기를 확인한 고정 크기 읽기와 실행별 파일 수·바이트 한도를 적용하며 음성 보존 파일과 적용 후보 미디어를 함께 계산한다. 음성 탭의 실제 자산 검토 플레이어는 다른 화면/프로젝트/미디어 재생과 문서 비활성화 때 정지한다. 이 개별 검토는 타임라인 배치 승인이나 Final 허가가 아니다. 구간 계획은 기존 WAV의 바이트·해시·PCM 규격·Cue/Asset/원문 결속·현재 시간 길이를 확인한다. 기존 시각과 관계를 보존한 채 측정 상태를 복원하고, 새 음원이나 음성 생성 Record를 만들지 않는다. 실제 검증 근거는 계획 Record에 남긴다. 모델 호출 후 파일을 다시 읽고 변경된 파일·오래된 Project는 게시하지 않는다. 편집 구간의 재검증은 별도 작업으로 수행하며, 외부 효과음·음악은 아래 준비·배치 경로를 사용한다. 작업별 예외를 묶은 상세 검토와 전체 작품 검증은 남은 범위다. 합성 엔진으로 Store 전체 흐름을 검증한 결과를 장시간 실제 Codex 실행 검증으로 해석하지 않는다.

## 외부 음향 준비와 자동 배치

Project 1.23은 음향 판정의 `occurrences`에 각 발생의 Cue ID, 원문 종류와 정확한 인용, 정보 ID, 근거를 저장한다. 새 발생은 모델 입력의 null Cue ID를 실행이 소유한 새 ID로 바꾸며, 기존 SOUND/MUSIC은 같은 Unit의 트랙을 재사용한다. 여러 시점의 소리를 각각 계획하고 각 Cue에는 해당 발생의 정보만 적용한다. 같은 소리가 지문과 효과음에 함께 기술된 경우 `supportingUnitIds`로 검증된 보충 인용을 연결해 중복 트랙을 만들지 않는다. 부모 정보 목록은 발생별 합집합이며 모든 부모 인용은 주 원문 또는 보충 근거에 포함되어야 한다. 같은 Unit 안에서 인용을 나누더라도 그 Unit의 기존 정보 하한은 완화하지 않는다.

미등록 발생의 시작은 주 Unit의 확정 Source Anchor 구간 안에 있어야 한다. 현재 컷이 이미 계획된 경우 `repair`의 `soundCueIds`가 사람 미확인·미측정·비보호 발생을 선택하며 콘티 전용 실행에서도 배치한다. 기존 Cue의 시작/종료 범위와 관계, 확정 Source Link, 컷·그림·원문·자산을 유지하고 각 대상 시각의 원문·공개 조건을 검사한다. 같은 실행의 완료한 repair는 반복하지 않는다. 별도 실행에서 여전히 미확인인 발생은 현재 범위 안에서 다시 검토할 수 있다. 발화 합성과 음향 지시 배치는 구분하며 실제 WAV 생성은 하지 않는다.

UI는 발생별 인용·트랙·보충 원문·정보·판단 근거와 실제 Cue의 계획 시각을 보여 주고 미저장 입력을 복원한다. 편집 저장은 제안이며 명시적인 음향 판정 확인은 별도다. 음원 또는 보호 컷에 묶인 전용 Cue의 원문·정보를 재지정하거나 제거하지 못한다. 발생별 근거가 없는 이전 자동 전용 트랙의 미확정 제안은 인용 수와 관계없이 다시 검토한다. 인용이 없다는 이유로 하나의 소리라고 판단하지 않는다. 미확인·음원 없는 비보호 상태만 자동 보완하며 수동 입력과 이미 확인한 판정은 자동 변경하지 않는다. 과거 여러 원문을 합친 트랙의 기존 검토 차단도 유지한다. Project 1.22→1.23은 이전 바이트·승인·기록을 재작성하지 않는 메모리 버전 이관이다. 과거 버전에 발생 필드를 끼워 넣는 입력은 거부한다. 모델 응답 계약은 모든 필드를 명시하도록 저장 스키마와 분리하며 빈 보충 목록도 반환한다.

장면 공통 음향은 같은 종류·본문·실제 파일/행 출처를 공유하는 지시 묶음으로 검토한다. 문서 어댑터가 여러 구간에 보존한 같은 지시를 독립적인 소리 발생으로 해석하지 않는다. 자동 모델에는 묶음의 모든 구간·원문·기존 판정을 전달하고, 적용할 구간 ID와 정확한 원문 인용·이유를 `sharedScope`로 기록한다. 재연·내레이션·패널이라는 모드만으로 음향을 생략하거나 반복하지 않는다. 일회성 동작 소리, 지속되는 환경음, 마지막 음악의 적용 범위를 원문과 대조한다.

공통 범위 제안은 실제 지시 목록·구간·인용·현재 구간의 필요 여부와 일치해야 하며, 직접 입력/확인한 판정과 모순될 수 없다. 다음 구간은 같은 적용 범위를 이어받는다. 다른 구간의 동작을 현재 음향 정보로 연결하지 않고, 현재 구간에서 소리로 드러나는 인용의 정보 하한만 연결한다. 현재 구간이 적용 대상이 아니면 `none`은 해당 구간에 추가 트랙이 없다는 뜻이다. UI는 전체 적용 구간과 현재 결론을 함께 보여 준다. 기존 자동 판정에 공통 범위 근거가 없거나 현재 판정과 충돌하면 출력 검토 항목으로 남기며, 미확정·음원 없는 비보호 트랙만 다시 계획한다. 사람 확인·음원·잠금·원문·기존 생성 기록을 바꾸지 않는다. Project 1.21→1.22는 메모리에서 버전만 이관하며 과거 공통 범위나 승인을 만들어 넣지 않는다.

PDF 음향 지시의 제목에 현재 구간 배치/추가 배치 없음/미판정/재검토를 표시한다. 원문 본문을 유지하며 유효한 판정의 적용 구간·공통 근거·현재 구간 판단 이유를 함께 담는다. 미확정 제안은 검토 전 상태이며, 원문 Snapshot·공통 범위·연결이 잘못된 저장 판정은 확인 플래그가 있어도 검토 완료로 출력하지 않는다. 외부 검토의 근거 문장에도 기존 PDF 비식별화 정책을 적용한다.

Project 1.21.0의 음향 판정은 `sourceEvidence`로 같은 구간의 ACTION·SOUND·MUSIC Unit과 정확한 인용을 연결한다. 원래 음향 칸이 `—` 같은 빈칸 표시여도 대본에 소리가 직접 적혀 있으면 그 인용을 트랙 본문으로 사용한다. 인용한 Unit의 정보 공개 조건을 모두 연결하며 존재하지 않는 문구·다른 구간·발화를 효과음으로 바꾸는 연결은 거부한다. 빈칸만 있는 전용 트랙은 기본 출력에서도 검토를 요구한다. 과거 미확정 자동 빈 트랙만 새 실행에서 재검토하고 직접 입력·확인·실제 음원이 있는 트랙은 유지한다. 1.20 저장본은 메모리에서 버전만 이관하며 근거·승인·과거 생성 기록을 만들어 넣지 않는다. 문서 전문 제외 정책에서도 대본 단위와 콘티 지시의 인용은 보존하고, 외부 공유 시 동일한 비식별화 규칙을 적용한다.

Project 1.20.0은 `music`·`ambience` Instruction의 판정을 원문 Dataset과 별도로 보관한다. 자동 실행의 `audio-instructions` 작업은 선택한 비보호 구간의 미판정 지시를 먼저 읽고 명시적 부재 또는 필요한 음향으로 판정한다. 같은 구간·종류의 기존 Cue로 충족하면 연결하고, 별도 음원이 필요하면 `unitId: null`·`instructionId`를 가진 준비 트랙을 만든다. 대본 Unit을 만들어 넣거나 환경 음향 설명을 낭독하지 않는다. 모델 출력은 지시 전체의 중복 없는 대응·기존 트랙 종류·정보 ID·출처 Snapshot을 검사한 뒤 생성 기록과 함께 제안으로 저장한다. 직접 입력·확인한 판정과 보호된 컷은 다시 계획하지 않는다.

음향 판정은 필요 여부, Cue ID, 소리로 드러나는 원문 정보 ID, 이유, 원문 Snapshot, 자동/수동 출처와 사람의 확인 상태를 구별한다. 연결된 기존 음향에도 지시의 정보 하한을 적용한다. 판정이 없거나 미확인이면 `AUDIO_INSTRUCTION_REVIEW_REQUIRED`로 Final을 차단한다. 판정과 원문·계획 시각을 검토한 음향 지시는 WAV 없이도 기본 Final에 포함한다. 실제 음원 부재와 재생 배치 문제는 `optionalAudioIssues`로 분리한다. 판정 확인은 파일·시각·그림 승인을 대신하지 않는다. 음향 탭에서 제안과 출처를 확인하고 수정·확인하며, 같은 트랙의 WAV 준비와 자동 배치를 이어간다. 미저장 입력은 프로젝트·지시·revision에 결속해 복원한다.

1.19→1.20은 메모리에서 버전만 이관하고 과거 파일과 승인을 유지한다. 이전 버전에 새 지시 필드를 끼워 넣은 입력은 거부한다. 원본 업데이트는 바뀌지 않은 지시·트랙을 보존하고 영향 구간의 판정과 트랙은 다시 계획하되 이전 자산·생성 이력을 남긴다. CSV는 구간별 판정·원문 출처를 보관한다. PDF·CSV 본문은 콘티 원문·계획 시각 검사를 사용하고, 실제 음성 재생은 추가로 실측 파일·배치를 검사한다. 실제 적용 범위와 검증 증거는 실행 Report를 따른다.

Project 1.12.0의 Audio Cue `timingStatus: prepared`는 효과음·음악 파일을 실측·정규화해 저장했지만 타임라인 배치는 아직 검증하지 않은 상태다. `startMs/endMs`는 이 상태에서만 허용 배치 범위다. 미등록 within-segment 음향의 준비는 원본 구간 전체를 범위로 삼아 기존 자동 초안의 임시 길이를 확정 길이로 오해하지 않는다. J/L컷은 명시한 기존 범위와 관계를 유지한다. 배치 대기 상태에서 범위를 직접 좁혀도 파일은 보존한다. 보호 컷의 원문을 공유하거나 범위와 겹치는 변경은 거부한다.

`POST /api/projects/:projectId/audio/:cueId/prepare`는 WAV와 expectedRevision을 받고 기존 Worker·Asset·ProjectStore 검사로 실제 파일을 보관한다. 기존에 배치한 음원은 이 작업으로 교체하지 않는다. 배치 대기 파일의 재선택은 새 Asset 버전을 만들고 이전 파일을 보존한다. Cue·Source·Text·그림 승인을 확정하지 않으며 `AUDIO_PLACEMENT_REQUIRED`로 실제 음성 재생을 차단한다. 기본 콘티 Final은 파일 준비 상태와 별도로 원문·계획 시각·검토 상태를 판정한다. 파일 자체는 개별 검토 플레이어에서 들을 수 있다. UI의 WAV 준비는 저장 후 제작 현황을 열며 실행 범위·한도를 선택한 자동 제작이 실제 배치를 이어간다.

구간 계획과 편집 컷 보완은 준비 음향의 실제 바이트·해시·PCM·대상을 검사하고 모델에 길이·허용 범위를 전달한다. 준비 음향만 정확한 파일 길이로 재배치하며 기존 measured/proposed 음원의 시각은 유지한다. 편집 보완 1.2.0은 미등록 발화와 준비 음향 각각에 audioTimings를 요구하며 1.0/1.1의 이전 결과는 준비 음향 없는 기존 범위로 읽는다. 소리의 배치와 Source Anchor를 한 후보에서 검사하며 확정된 정보 하한·원문 순서·Coverage를 우회하지 않는다. 배치 오류만 유한 보정하고 손상된 실제 파일은 중단한다. 같은 준비 Asset을 재사용하며 효과음 낭독·가짜 Speech Record·새 음향 파일을 만들지 않는다. 적용 직전 파일·Project를 다시 검사한다. 1.11→1.12는 메모리에서 버전만 이관하고 원본 Version 파일과 과거 Record는 보존한다.

## 제작자 시간순 검토

자동 제작의 결과 불러오기는 최신 저장본의 초안 재생 화면을 연다. 재생·일시 정지·시간 탐색과 현재 그림의 편집 이동을 제공한다. 화면은 프로젝트 화면비에 맞춰 여백을 두며, 미승인 결과가 포함된 검토용 초안임을 계속 표시한다. 글자는 독립 트랙의 현재 활성 Cue를 합성하고 음성은 기존 실측·Cue 범위 재생 규칙을 따른다. 그림 편집에서 검토·재생성 표시를 진행하며 재생 자체는 어떤 승인 상태도 변경하지 않는다.

`producer-playback.ts`는 기존 시간순 그림 선택·Source Coverage·Hold·전환 노출 검사를 공유하며 사람의 `pending` 그림 검토 상태만 허용한다. `rejected`, 미정 원문, 공개 시점 위반, 없는 이미지와 잘못 연결된 자산은 계속 차단한다. Hold는 이전 컷의 실제 마지막 표시 프레임을 선택하고 전환은 다음 컷의 조기 정보 노출을 검사한다. 안전 출력과 Final의 기존 승인은 그대로 필요하다.

검토 전용 `GET /api/projects/:projectId/review/visual`과 `/review/transition`은 `atMs`와 `revision`을 모두 받는다. 서버는 같은 revision에서 결정한 이미지의 실제 파일·해시·디코딩·연결을 검사하고, 읽는 중 Project가 변경되면 오래된 응답을 거부한다. 검토용 응답 표식과 revision을 반환하며 HTTP 캐시는 사용하지 않는다. 브라우저는 동일한 그림·활성 원문 구간 안에서 받은 Blob만 재사용하고 Frame·Source·revision 변경 시 검증 요청을 교체한다. 기존 안전 출력 API에 검토 채널을 추가하지 않으며 PDF·CSV·Final의 판정은 바뀌지 않는다.

## 긴 제작 내용의 PDF 출력

PDF는 공통 출력 판정을 통과한 Projection만 렌더링한다. 상세형은 프레임마다 새 페이지에서 시작하며 용지·방향·그림 목록 선택은 아래 제작용 출력 선택 계약을 따른다. 그림은 프로젝트 화면비 안에 원본 비율을 보존해 맞추고, 컷 시간·카메라·전환·Frame ID와 표시/평가 시각을 나란히 제공한다. 행동·프레임 설명·원문 연결·글자/음향 큐·공개 기준·차단 사유를 실제 글꼴 폭으로 줄바꿈하고 후속 페이지로 이어 쓴다. 고정 높이 말줄임이나 본문 자동 요약은 사용하지 않는다. 후속 페이지는 같은 프레임 순번과 이어지는 항목명을 표시하며 전체 페이지 번호를 제공한다.

컷과 겹치는 Text/Audio Cue는 원래 ID·종류·절대 타임코드·정확한 ms 범위·본문·검토 상태를 표시한다. 글자 본문은 `reviewTextOutput`, 음성 본문은 `reviewAudioPlaybackAt`의 허용 결과만 포함하며 차단되면 본문 대신 상태를 출력한다. 이미지 승인과 실제 자산 검사, Final의 전체 차단은 유지한다. External Projection은 프레임 설명과 새 큐 필드까지 같은 비식별화 정책을 적용하고 bitmap을 포함하지 않는다. 같은 Projection·생성 시각·글꼴/Renderer의 결정적 출력 계약을 유지한다.

프레임 위 글자는 아래 공통 조판으로 검토 화면과 PDF에 연결한다. 상세형과 그림 비교 목록 모두 선택한 프레임의 실제 출력 판정을 사용한다.

## 공통 글자 조판

Project 1.13.0의 `textLayout`은 초기 프리셋 1.0.0 또는 저장한 사용자 설정이다. 고지·소품 글자·대사 자막의 위치, 짧은 변 기준 글자 크기, 줄 간격, 안전 여백, 안쪽 여백, 영역 간격과 최대 줄 수를 관리한다. 원본 Dataset과 글자 본문·시각·승인은 변경하지 않는다. Source Update와 자동 생성의 현재 Project Snapshot에도 같은 설정을 보존한다. 1.12 파일은 메모리에서 초기 프리셋을 추가하며 원본 바이트·이전 Snapshot 해시를 유지한다. 이전 버전에 알 수 없는 조판 필드가 있으면 버전 오류로 거부한다.

`rendering/text-layout.ts`는 실제 글꼴 폭으로 줄을 나누고 같은 위치의 글자를 쌓는다. 본문을 자르거나 임의 축약하지 않는다. `text-font.ts`가 생성한 Glyph 경로·좌표를 브라우저 SVG와 PDF 프레임에 공유한다. 브라우저는 활성 글자 집합·revision·maturity가 바뀔 때 조판을 요청하며 이전 응답을 버린다. 요청 시점과 응답의 Project·revision을 검사하고 안전 정책에서 허용한 본문만 반환한다. 초안/전환 안내는 실제 화면 글자와 겹치지 않도록 프레임 밖에 둔다.

겹침·넘침·지원하지 않는 Glyph는 해당 글자의 렌더링을 차단하고 구체적인 검토 항목을 낸다. Final Readiness HTTP·목록·Final PDF/CSV·Review Bundle은 실제 설정 글꼴과 전체 Cue 경계를 검사한다. 프레임 스냅샷 사이에서만 발생하는 문제도 포함한다. 구조·원문·미디어 도메인 검사는 유지하며 조판 검사는 출력 경계에서 함께 수행한다. External PDF는 Glyph의 입력 본문과 이미지도 제거한다. PDF에 조판 버전과 사용한 글꼴 SHA-256을 기록한다.

프로젝트 글꼴·언어와 Cue별 표현은 아래 계약을 사용한다. 개별 표현이 없는 문구는 공통 프리셋으로 배치한다. 작품별 전역 프리셋 계획은 아래 자동 배치 계약을 사용한다. 기본 프리셋 적용을 Codex의 개별 작품 가독성 판단이나 사람 승인으로 표시하지 않는다.

자동 구간 계획은 구조 검증을 통과한 후보의 모든 글자 경계를 실제 출력 글꼴로 검사한다. 각 Cue의 단독 줄 수·문제와 동시 표시 문제를 구분하며 현재 프리셋·글꼴 해시·검사 결과를 모델에 돌려준다. 표시 시각으로 해결 가능한 미확정 Cue만 기존 `maxModelCorrections` 한도 안에서 다시 계획한다. 본문·종류·권한·읽기 기준과 보정 대상 밖의 시각을 보존하며 원문·전체 구간·공개 순서는 기존 후보 검증을 통과해야 한다. 확정 시각은 보정 대상이 아니다. 시작이 고정된 Placement는 원본 종료가 미정일 때 종료만 보정한다. 이 구간 시각 보정에서 글자 크기·설정을 바꾸거나 본문 축약·짧은 깜빡임으로 겹침을 없애지 않는다.

해결되지 않은 조판 문제는 후보의 예외와 현재 Readiness에 남는다. `textReview` 1.1.0은 이번 신규 Generation Record에만 저장하고 검사한 글꼴 해시를 참조 근거로 기록한다. 모델 호출 전후의 글꼴이 다르면 후보를 거부한다. 편집 컷 보완 작업은 글자 시각을 유지하고 검사 근거만 남긴다. 초안 본문도 공통 조판 검사 대상이므로 사람의 시각 확정 전에 검토 화면에서 글자 설정으로 이동할 수 있다. 프로젝트의 읽기 기준 검사를 함께 적용한다. 설정 통과를 사람의 실제 가독성 검토 완료로 간주하지 않는다.

### 개별 문구 표현

Project 1.19의 선택적 `TextCue.presentation` 1.0.0은 공통 프리셋과 구별되는 문구별 배치다. `x/y/width`는 화면 비율이며 x는 영역 왼쪽, y는 `verticalAnchor`의 top/center/bottom 기준점이다. `fontSize`는 짧은 변의 비율이다. `alignment`, 정수 `layer`, 대비를 유지하는 `dark/light` 배경을 저장한다. 줄 간격·안쪽 여백·최대 줄 수·안전 여백과 글꼴은 공통 설정을 따른다. 낮은 레이어부터 그리지만 레이어로 겹침 검사를 우회하지 않는다. 실제 Glyph로 계산한 전체 영역이 안전 여백 안에 있어야 하며 본문을 생략하지 않는다. 화면 SVG·PDF는 같은 좌표·Glyph·색을, JSON·CSV는 실제 Cue 표현을 보존한다.

자동 계획 응답의 `cuePresentations`는 모든 실제 Cue ID에 중복 없이 결론 하나를 요구한다. 공통 프리셋 사용은 null, 개별 생성은 mode=automatic이다. mode=manual인 기존 표현과 승인 출력의 모든 표현은 그대로 보존한다. 잘못된 ID·중복·누락·수동 덮어쓰기는 제한된 보정 대상이며 해결되지 않으면 적용을 거부한다. 새 기록의 templateVersion은 `automatic-text-layout-1.2.0`이다. 재계획 해시는 수동 표현을 포함하고 자동 결과 자체로 반복 실행하지 않는다. 과거 기록의 현재 일치 여부는 표현 값과 Cue ID 집합까지 대조하며 승인 근거로 사용하지 않는다.

PATCH `/text/:cueId/presentation`은 명시적 revision에서 선택 Cue만 manual로 저장한다. DELETE는 공통 배치로 되돌리고 둘 다 자동 계획 입력 해시를 무효화한다. POST `/text/:cueId/presentation/preview`는 저장하지 않으며 호출 전후 revision을 검사한다. 기존 본문·시각·근거·미디어·승인은 유지하고 Final 검사는 현재 조판으로 다시 계산한다. 브라우저 미저장 입력은 프로젝트·Cue별로 복원하며 입력/기준이 바뀌면 오래된 미리보기를 숨긴다. 큰 검토 창은 같은 시점의 제작자 검토 그림과 미저장 글자 SVG를 실제 화면비 안에 합성한다. Cue의 반열린 표시 구간 안에서 이동하며 기존 Program Monitor와 전환 노출·불투명도·클립 계산을 공유한다. 이동 중 이전 글자를 숨기고 요청을 취소하며 프로젝트·revision·atMs가 다른 응답을 거부한다. 미승인 그림은 검토에 포함하되 원문·정보 Gate·실제 파일 검사를 유지한다. Esc/닫기는 원래 버튼으로 돌아가고 저장·승인·미디어 생성은 하지 않는다.

Text Mapping 재조정과 Source Update는 같은 명시적 Placement/Mapping/Unit 근거의 표현을 보존한다. 여러 기존 Cue가 같은 근거를 가진 경우 임의 선택하지 않고 구체적 오류를 낸다. 1.18 저장본은 메모리에서 버전만 올리며 표현을 생성하지 않는다. 1.18에 선언되지 않은 presentation이 있으면 버전 오류로 거부하고 원래 파일은 변경하지 않는다. 표현 기술 검증은 실제 작품 전체의 가독성·피사체 가림 검토를 대신하지 않는다.

### 프로젝트 글꼴과 언어

Project 1.18의 선택적 `textTypography` 1.0.0은 등록 ID·SHA-256·정규 BCP 47 언어 태그를 저장한다. 1.17 저장본은 메모리에서 버전만 올리고 글꼴 선택을 만들지 않는다. 당시 알 수 없는 선택 필드는 거부하고 원래 파일 바이트를 보존한다. 미지정 콘티는 기존 `pdfFontPath`를 사용한다. 추가 `textFonts`는 서버 설정의 명시적 ID·이름·파일 경로 목록이며 프로젝트 간에 선택값을 복사하지 않는다. ID·해시 불일치, 없는 파일·컬렉션·손상 파일을 대체하지 않는다. 단일 글꼴 파일은 읽기 전에 32 MiB 한도를 검사한다.

등록 목록 API는 사용 가능한 실제 이름·해시와 사용할 수 없는 항목의 원인을 구별한다. 하나의 잘못된 등록 때문에 나머지 선택을 숨기지 않는다. 제작 설정에서 글꼴·언어를 미리 보고 한 revision으로 저장하며 기존 원문·시각·자산·승인을 보존한다. 브라우저 초안·다른 탭·revision 충돌은 공통 복원 계약을 따른다. 미리보기는 입력 전체·revision·글꼴 해시에 결속하고 저장하지 않는다. 글꼴 복원이 필요한 프로젝트도 목록과 편집 화면을 열 수 있으며 최종 출력은 계속 차단한다. Source Update는 현재 선택을 보존한다.

자동 글자 배치는 실제 등록 ID·해시와 글꼴별 미지원 Cue ID를 모델에 제공한다. 신규 응답은 글꼴·언어를 요구하고 실제 목록에 없는 선택을 유한 보정한다. 저장한 선택이나 승인된 출력의 표현을 덮지 않는다. 선택한 글꼴로 실제 단독·동시 조판을 다시 검사하고 지원 문자 문제가 다른 등록 글꼴로 개선 가능하면 보정에 포함한다. 생성 기록 `automatic-text-layout-1.1.0`에 선택·입력·실제 해시·남은 문제를 기록하며 1.0 기록의 읽기를 유지한다. 계획 해시는 선택을 포함하고 수동 저장은 재계획 필요 상태로 만든다. 미지원 문자·겹침·넘침은 최종 검사를 우회하지 않는다.

Program Monitor·PDF 그림은 같은 Glyph 경로를 사용한다. PDF 설명 본문은 기본 글꼴을 유지하고 두 해시와 언어를 PDF metadata에 기록한다. External PDF에는 프로젝트 선택과 원문 조판을 제거한다. 검토 자료 미리보기·게시 기준은 화면 글꼴과 설명 글꼴의 실제 해시를 함께 검사한다. 언어는 문자 분할에 전달하며 번역·자막 생성·OpenType 언어별 대체 Glyph 선택을 의미하지 않는다. Cue별 표현은 다음 계약을 사용하며 작품 전체의 가독성 검토는 계속 필요하다.

## 구현 진행 원칙

실행 연결 → 후보 계약과 순수 검증 → staging 음성 → 실행 관리/API → 기준/그림 생성 → 검토 UI·재생·재생성 → 출력·범용 파일럿 순으로 통합한다. 기존 미완료 작업을 보존하고 필요한 공통 로직만 추출한다. 설정 분석의 변경 영향 표를 따라 해당 결과만 재계산하며 기술적 실행 완료 후 사용자 검토 단계로 인계한다.

## 컷·프레임 표현 수준

자동 실행의 `density` 1.0.0은 `source-led`(원문에 맞춤), `concise`(간략), `detailed`(상세) 선호와 `longHoldReviewMs`를 저장한다. 초기값은 원문에 맞춤·15,000ms이며 작품의 고정 컷 수나 최대 컷 길이가 아니다. 간략은 같은 구도의 연속 행동을 필요한 키 프레임으로 묶고, 상세는 손동작·시선·화자 반응·상태 변화를 구별하도록 계획한다. 직접 원문 공개에 필요한 프레임은 어느 선호에서도 생략하지 않는다. 시작은 필수이며 중간 상태에 key, 끝 상태를 별도로 검토할 필요가 있을 때 end를 계획한다. 의미 없는 균등 분할이나 같은 그림 추가로 개수를 맞추지 않는다.

모델 입력과 실행 Snapshot·settingsHash에 선택 값을 결속하고 재개 때 유지한다. 이전 실행에 이 필드가 없는 경우는 명시적인 구 계약으로 읽으며 설정·이벤트·과거 해시를 재작성하지 않는다. 이전 기록에 새 선호를 추정해 넣지 않는다. 새 화면은 명시 추천을 제공하고 최근 실행에 저장된 상세도는 다시 보여 준다. 상세도 변경은 새 원문 뼈대의 다음 자동 구간 계획에 적용한다. 이미 편집·생성한 컷은 기존 보완 범위를 지키고, 잠금·확정 컷·승인 그림을 재분할하거나 교체하지 않는다.

후보의 실제 Source 파생 프레임까지 세며, 그림 생성 수와 black/hold-previous의 비생성 수를 구분한다. 한 sourced 프레임을 다음 프레임 또는 컷 끝까지 표시하는 구간이 검토 기준보다 길면, 기존 모델 보정 한도 안에서 원문의 의미 있는 상태 변화를 다시 검토한다. 의도된 정적 장면은 이유를 남기고 유지할 수 있다. 남은 긴 표시는 기술 실패나 Final 차단으로 위장하지 않고 사람의 연출 검토 대상으로 둔다. 실제 예산 초과는 기존 Frame/Job/Image 한도로 계속 차단한다.

신규 Generation Record의 `densityReview`에는 설정·검사 기준 revision·구간·실제 컷/프레임/그림 대상/역할별 개수와 긴 표시 구간을 보존한다. 기존 편집 컷 보완은 시각을 바꾸지 않고 같은 검토를 기록한다. 제작 현황은 불러온 현재 Project에서 같은 순수 함수를 사용해 재계산하고 해당 컷의 그림 편집으로 연결한다. 서버 결과보다 오래된 화면은 최신 결과 불러오기를 요구하며, 현재 revision의 계산을 과거 생성 당시의 검토라고 표시하지 않는다. 사용자 승인 상태는 변경하지 않는다.

## 초안 읽기 시간

Project 1.14.0의 `textReadability` 1.0.0은 공백을 제외한 Unicode grapheme 묶음 수, 초당 읽기 수, 최소/최대 유지 시간의 명시적 초안 기준이다. 초기값은 12개/초·1,000ms·8,000ms이며 산업 표준이나 원본 확정 지시로 해석하지 않는다. 필요한 시간은 `max(minHoldMs, ceil(graphemes × 1000 / graphemesPerSecond))`다. 필요한 시간이 최대값을 초과하면 원문을 줄이지 않고 `TEXT_READING_WINDOW_EXCEEDED`를 남긴다. 빠른 표시는 `TEXT_READING_TOO_FAST`, 과도한 유지는 `TEXT_HOLD_TOO_LONG`로 구별한다. 사용자 확정 시각은 이 초안 정책으로 재승인 요구하거나 자동 변경하지 않는다.

읽기 기준은 설정 API에서 expectedRevision을 검사해 한 revision으로 저장하고 Source Update·전체 실행 Snapshot·신규 생성 Record에 보존한다. 저장만으로 시각·원문·자산·승인 상태를 바꾸지 않는다. 1.13 저장본은 읽기 전용 메모리 이관으로 초기 기준을 추가하며 디스크·과거 해시를 보존한다. 구버전의 알 수 없는 읽기 설정은 버전 오류다.

자동 후보의 단독 조판 문제·읽기 문제·시간 이동 권한을 나누어 보정 대상을 정한다. 고정 Placement 시작과 알려진 원본 종료, 확정 Canonical 매핑과 사용자 확정 시각은 유지한다. 미정 종료·이동 가능한 Cue만 기존 모델 보정 한도 안에서 조정하고 전체 Source/Gate/고정 구간 검사를 다시 통과해야 한다. 과도하게 긴 초안은 최대 유지 시간까지 줄일 수 있지만 필요한 읽기 시간보다 짧게 하거나 정상 후보를 줄여 겹침만 없애지 않는다. 제한 내 미해결 후보는 구체적인 검토 항목을 유지한다. 읽기 문제는 시각 확정 전부터 검토 화면에 표시하며 설정으로 바로 이동할 수 있다. 효과음·음악이나 문자를 읽는 가이드 음성을 추가하지 않는다.

## 작품 전체 글자 배치 자동 계획

Project 1.15.0의 `textLayoutControl` 1.0.0은 `automatic`/`manual`과 마지막 계획의 입력 해시를 보존한다. 신규 가져오기는 자동이며 1.14 이전 저장본은 기존 사용자 소유권을 증명할 수 없어 수동으로 메모리 이관한다. 저장본·과거 이벤트·감사 해시는 재작성하지 않는다. 제작 설정에서 자동을 명시적으로 선택하면 입력 해시를 비워 다음 실행에서 재계획한다. 배치 수치나 종류별 위치를 직접 저장하면 수동으로 전환한다. Source Update는 설정을 보존하며 변경된 Dataset·화면비는 다음 실행의 새 계획 근거가 된다.

새 실행의 `textLayoutPlanning`은 자동 계획 또는 기존 배치 보존이다. Project와 Run 설정이 모두 자동이고 글자가 있으며 입력 근거가 바뀌었을 때, 실행기는 `text-layout` 작업을 한 번 등록한다. 전역 프리셋이므로 선택 구간과 별개로 작품 전체에 적용된다는 점을 설정 화면에 표시한다. 이전 실행에 없는 설정을 소급 추가하거나 과거 해시를 바꾸지 않는다. 작업은 생성 결과의 전체 Snapshot·revision·실제 글꼴 해시와 결속하고 기존 후보 적용·복구 계약을 사용한다. 사용자 편집으로 Snapshot이 바뀌면 후보 적용을 거부한다.

Codex 입력은 실제 문구·종류·기존 시각·화면비·현재 프리셋·글꼴 Glyph 지원과 폭이다. 출력은 기존 프리셋 Schema 안의 배치와 이유뿐이다. 글자마다 단독 조판을 검사하고, 현재 Draft 출력에서 허용한 동시 글자 집합의 겹침도 검사한다. 미해결 원문 권한을 배치 변경으로 확정하지 않는다. 겹침·넘침은 기존 `maxModelCorrections` 한도 안에서 보정하며 지원하지 않는 Glyph와 남은 문제는 기록한다. 글꼴 바이트가 호출 전후 달라지면 후보를 거부한다. 이 작업은 본문·Cue 종류·시각·읽기 기준·그림·승인 상태를 변경하지 않는다. 확정/잠금 컷 또는 승인 그림이 있으면 모델이 같은 배치와 보존 이유만 반환할 수 있다. 글자의 시각 확정은 배치 승인으로 해석하지 않으며 해당 시각은 그대로 보존한다.

신규 `automatic-text-layout-1.0.0` 생성 기록에 실제 모델·응답·입력·사용 글꼴·잔여 문제를 저장한다. 설정 화면은 최근 제안 이유와 당시 문제, 현재 프리셋과 일치 여부를 표시한다. 이후 수동 편집한 배치를 과거 자동 제안으로 표시하지 않는다. 모델이 문구를 숨기거나 작게 만들어 기술 검사를 통과했다고 사람이 읽기 좋다고 확정하지 않는다. 현재 상태의 조판·원문·실제 자산·Final 검사를 계속 적용하며, 구간 계획의 시각 배치 검토와 사용자 결과 검토로 이어진다.

## 검토 재생 속도 — B05

브라우저의 프로젝트별 검토 선호는 0.5·0.75·1·1.25·1.5·2배다. 기록이 없으면 1배, 잘못된 JSON·프로젝트 결속·지원하지 않는 값이면 재선택 전 재생을 차단한다. 명시 선택의 저장 실패는 현재 화면에만 적용됨을 알리고 기록을 성공으로 가장하지 않는다. 다른 탭의 변경은 현재 청취에 끼어들지 않으며 프로젝트 재열기 때 읽는다. 복원·전환으로 재생을 시작하지 않는다. 이 선호는 제작 원문·합성 설정·실제 WAV·Project revision·출력 및 승인과 분리한다.

원본 ms의 playhead를 단조 시계 경과 시간×배속으로 계산한다. 배속 변경은 현재 위치에서 시계를 다시 시작하고 이전 Audio·timer·Promise 수명을 종료한다. Media playbackRate는 같은 배속, pitch는 유지 요청, 종료 timer는 남은 원본 ms÷배속을 사용한다. Cue 범위·화면·글자·전환·공개 판정·음량과 페이드는 원본 playhead를 공유한다. 실제 음원 위치가 150ms보다 벗어나면 원본 시각에 맞추며 metadata 대기 중에도 최신 요청 위치를 보존한다. 검토 속도는 음원 지연의 무손실 보장이나 시간표 변경이 아니다. 개인 음원 전체 청취에도 같은 선호를 적용한다. 실제 작품 호흡과 전체 길이는 1배에서 검토한다.

## 화자별 합성 음성 — B05

자동 실행 Snapshot의 `voice`는 공통 음성, `speakerVoices`는 실제 원문의 화자 ID별 이름·말하기 속도 선택이다. 화자 미지정 발화는 null로 구별하며 등장인물 나열 순서·이름 언급·화면 등장만으로 음성 출연을 추가하지 않는다. `voicePlanning=configured` 또는 이전 실행에서는 개인 선택이 없는 발화에 공통 음성을 사용한다. 새 권장 실행의 `voicePlanning=automatic`은 실제 원문 화자·언어·역할과 설치된 이름·언어·예문을 Codex에 보내 빈 배정을 계획한다. 직접 지정한 개인 선택이 우선한다. 이전 실행의 미지정 배열과 다른 제작 설정은 추가·재작성하지 않으며 기존 해시를 보존한다. 선택값은 Project 원본과 분리된 브라우저 시작 초안으로 보관하고 실행 시작 시 고정한다.

`GET /api/automation/speech-voices`는 설정된 로컬 음성 명령이 반환한 정확한 이름·언어·예문을 제공한다. 빈 목록·해석 실패·중복 이름·시간 초과를 명시하고 원격 다운로드나 다른 음성으로 대체하지 않는다. 실행 전에는 선택 구간의 미등록·비보호 발화에 실제로 필요한 음성만 설치 목록과 대조한다. 음성 없는 영상·기존 음원·사용하지 않는 공통 음성 때문에 새 설치를 요구하지 않는다. 실제 생성 직전에도 설치 여부를 확인한다. 사라진 화자 설정은 보존하여 명시적 제거를 요구하고 다른 인물에 재배정하지 않는다.

구간 생성·수동 구간 보완은 같은 화자 선택 함수를 사용한다. 합성 입력 전에 목소리를 결정해 임시 음원의 입력 해시·캐시 재사용·실제 결과 검사에 결속한다. 생성 기록의 model·prompt와 자산 설명에 실제 음성과 속도를 보존한다. 원문·기존 WAV·배치·사람 승인은 바꾸지 않는다. 개별 CODEX VOICE/RETAKE 대기 요청은 기존 앱 공통 음성을 사용하므로 화면에 차이를 안내한다. 선택 발화의 부분 재생성은 아래 별도 Run 계약을 사용한다. 선택 발화의 발음 보완은 아래 재생성 계약을 사용하며 작품 전체 청취는 남은 B05 작업이다. 인물별 연기 품질을 보장하지 않는다.

음성 자동 배정은 합성에 앞선 `voice-casting` 작업이다. 선택 구간의 미등록·비보호 발화에서 기존 배정과 개인 선택이 없는 화자만 요청한다. 모델의 중복·누락·외부 화자, 설치되지 않은 이름, 판단한 언어와 음성 locale의 불일치를 검사하며 기존 유한 보정 한도를 사용한다. 지원 언어 부재는 구체적인 오류로 중단한다. Project 1.17의 선택적 `voiceCasting`에 원문 해시·화자별 음성/속도·이유·원문 Unit ID·생성 ID를 기록한다. 설치 목록과 실제 응답·배정 결과는 append-only GenerationRecord에 결속하며 일반 Run 후보·원자 적용·Commit 정산을 사용한다. 실제 합성 직전에 선택을 재검증하고 음성 캐시도 해당 선택에 결속한다.

같은 원문은 다음 구간·새 실행에서도 배정을 재사용하며 현재 원본 해시가 다르면 새로 계획한다. Source Update는 과거 배정과 생성 근거를 보존하되 새 원문에 자동 재사용하지 않는다. 기존 WAV·타임라인·사람 승인은 바꾸지 않는다. 이전 Project는 버전만 메모리에서 이관하고 voiceCasting을 추가하지 않는다. 웹은 자동/직접 방식과 배정 결과·이유, 원문 변경을 표시하며 복원만으로 새 작업을 실행하지 않는다.

## 실제 음원 기반 음량 계획

Project 1.16.0의 Audio Cue `mix`는 −30~0dB 음량, 페이드 인/아웃, 자동/수동 방식, 계획 입력 해시와 이유를 저장한다. 이전 파일은 버전만 메모리에서 이관하며 음량을 추정해 추가하지 않는다. 미지정 음원은 기존 원래 음량으로 재생한다. `audioMixPlanning=automatic`인 새 실행은 선택 구간의 실측 음원 배치·그림 작업 뒤 `audio-mix`를 등록한다. 이전 Run 설정과 해시는 재작성하지 않는다. 수동 음량·확정/잠금 컷·승인 그림과 공유/겹치는 음원은 보존한다. 원문·파일·시작/종료·속도·승인 상태는 변경하지 않는다.

계획 입력은 원문·실제 Asset·배치·겹치는 음원과 수동 음량에 결속한다. 한 구간의 대상과 겹치는 최대 256개 Cue, 실제 WAV 합계 512MB를 순차 검사한다. 기존 파일 제한과 PCM 검사를 공유하며 표본 계산은 일정 묶음마다 이벤트 루프에 제어를 돌려주고 취소를 확인한다. RMS와 표본 피크는 실제 파일 전체의 값이며 LUFS·진성 피크·렌더링한 믹스 클리핑 측정이 아니다. 모델 전후에 실제 WAV 해시·형식·길이를 재검증하고 현재 Project 해시/CAS로 후보를 원자 적용한다. 같은 바이트를 여러 Cue에서 써도 개별 배치 근거는 남기고 Generation Record의 참조 해시 집합은 중복하지 않는다.

Codex는 대상별 음량·페이드만 반환한다. 발화 페이드는 음절 보존을 위해 자동 계획에서 0ms이며 음향 페이드 합계는 실제 길이를 넘을 수 없다. 겹치는 표본 피크의 보수적 합 0.95를 검토 기준으로 사용하고 기존 유한 모델 보정 한도 안에서 조정한다. 해결할 수 없는 겹침, 무음, 최대 진폭 표본, 미측정 주변 음원은 기록과 음성 탭에서 확인한다. 검토 경고를 원본 복원·음질 승인으로 바꾸지 않는다.

`PATCH /api/projects/:projectId/audio/:cueId/mix`는 `expectedRevision`과 명시적인 `mix` 입력을 받는다. 음성 탭에서 값을 수정하면 수동으로 전환하고 저장한 뒤 재생에 적용한다. 개별 검토는 저장 음량과 원본을 비교하며 시간순 재생도 같은 음량·페이드 함수를 쓴다. Seek와 Cue 종료·화면 이동 시 정리 규칙은 유지한다. JSON에는 설정·근거, CSV에는 재생값, PDF에는 음량·페이드 지시를 포함한다. 원본 WAV를 덮거나 혼합 WAV를 출력하지 않는다. 작품 전체 청취 검증은 남은 B05 작업이다.

## 제작용 출력 선택

`StoryboardOutputOptionsSchema` 1.0.0은 원본 Project와 별도로 PDF/CSV 출력 선택을 정의한다. 용지는 A4/A3와 가로/세로, 상세 제작 콘티와 그림 비교 목록을 제공한다. 상세형은 프레임별 본문을 후속 페이지로 이어 쓰며 선택한 연출·원문·글자·음향을 담는다. 비교 목록은 표지와 페이지당 최대 2/4/6개 그림·시각·식별자·검토 상태만 담는 요약이다. 긴 식별자가 칸에 들어가지 않으면 자르지 않고 상세형 또는 낮은 밀도를 요구한다. 비트맵과 글자 합성의 화면비·공통 Glyph 판정은 유지한다.

프레임 선택은 전체 또는 컷별 첫 키 프레임 우선의 대표 한 개다. 키가 없으면 시작 프레임, 그것도 없으면 시간순 첫 프레임이다. 승인 여부로 대표를 바꿔 차단을 숨기지 않는다. 구간 목록은 입력 순서를 유지하며 알 수 없는 구간·중복·빈 선택을 거부한다. 선택한 Shot/Frame만 원본에서 투영하고 Project의 시간표·독립 트랙·참조를 잘라 새 프로젝트로 해석하지 않는다. Final은 전체 Project·실제 자산·전체 글자 배치의 공통 판정을 먼저 통과해야 한다.

기술 CSV는 기존 열 구조를 유지하며 제작용 CSV는 한 컷당 읽을 수 있는 본문과 시각·음량·검토 사유를 담는다. 원문·글자·음성 본문은 기존 출력 권한을 사용하고 수식 접두사 escape·UTF-8 BOM·CRLF를 공유한다. 선택한 내용만 내보내도 차단 사유는 항상 남긴다. 제작용 CSV의 내용 선택과 기술 CSV 전체 필드는 서로 구분한다.

웹의 출력 설정은 프로젝트 ID별 브라우저 저장 영역에 명시적으로 저장한다. 저장 오류·손상·원본 변경으로 사라진 선택 구간을 숨기지 않는다. 다운로드는 설정 Snapshot과 revision을 요청에 보내며 서버는 시작 및 렌더링 뒤 revision을 대조한다. 실패 응답·잘못된 MIME은 파일로 저장하지 않고 화면에 표시한다. 파일 이름 뒤에 실제 revision과 draft/final을 붙이며 경로 문자는 거부한다. 저장 위치는 브라우저 다운로드 설정이다. 편집 가능한 프로젝트 JSON은 전체 프로젝트를 유지한다.

출력 선택 기록은 같은 Project의 revision·정규화 모델 해시·옵션·Shot/Frame 목록을 남기는 별도 JSON이다. 재가져오기 파일 또는 최종 승인 증명이 아니다. Review CLI의 `--output-selection`은 해당 기록의 Project/revision을 검증해 PDF와 CSV에 적용한다. Bundle Manifest는 선택 옵션과 실제 목록, 선택 대상 산출물 및 나머지 JSON·감사·미디어의 전체 작품 범위를 명시한다. External은 동일한 비식별화 규칙으로 신규 필드까지 처리하고 원본 이미지/미디어를 포함하지 않는다. 원본 저장소 읽기 전용 검사·출력 게시·Manifest 해시 계약은 기존 경로를 사용한다.

## 검토·전달 패키지

B13 웹 화면은 사용 목적(검토·제작 전달·보관), 수신자, 내부/외부 범위, 초안/최종, 이름·버전, 문서 전문·생성 프롬프트·미디어 포함과 저장할 상위 폴더를 받는다. 기존 상위 폴더 안에 `이름-버전-draft/final-r수정번호` 새 폴더를 만들며, 이미 존재하는 폴더·파일·symlink는 덮어쓰지 않는다. 전달은 파일 생성까지이며 외부 메시지·업로드를 실행하지 않는다.

PDF·CSV만 출력 설정의 구간·프레임 선택을 사용한다. JSON의 대본 단위·연출·참조·검증 기록과 선택한 미디어는 작품 전체이며, 입력 문서 전문 제외를 모든 이야기 본문 제외로 표시하지 않는다. 내부용의 전문·프롬프트 제외는 원문 대신 범주·해시를 남긴다. 외부용은 전문·프롬프트·미디어를 포함할 수 없고 기존 비식별화·그림 자리 표시자 정책을 따른다. 추가 문구는 줄별 문자 그대로 매칭하도록 정규식 문자를 escape한다. 선택 정책과 목적·수신자를 Manifest에 기록하며 외부용은 이 메타데이터도 비식별화한다. 이전 CLI의 delivery 필드 없는 내부 출력은 유지한다.

`POST /api/projects/:projectId/review-bundles/preview`는 실제 원본·Version·Asset·글꼴·전체 Final 판정과 경로를 읽어 파일 수·미디어 바이트·출력 경로를 반환한다. 미리보기 기준은 입력 전체, revision·원본 해시, 상위 폴더 dev/ino, 글꼴 해시와 Build에 결속한다. `POST /api/projects/:projectId/review-bundles`는 이를 다시 계산해 다르면 재확인을 요구하고, 기존 읽기 전용 Archive/Publisher로 파일을 게시한다. 원본 Project의 승인·Asset·기록·revision은 변경하지 않는다. 서버당 미리보기/생성 I/O 하나, 웹 미디어 합계 256 MiB 한도를 적용하고 자동 재시도하지 않는다. `/api/review-bundles/status`는 활성 Project와 미디어 한도를 제공한다. 변경 HTTP는 같은 Origin만 허용한다.

화면은 설정·Project revision 변경 때 이전 미리보기를 무효화하고 결과를 실제 생성 당시의 경로·범위·파일 해시로 표시한다. 생성 뒤 편집기 재가져오기 JSON과 검토용 JSON을 구별한다. 미리보기를 거쳤어도 Final은 작품 전체·실제 파일·저장 정지 상태를 재검사한다. 패키지 입력과 생성 당시 결과 기록의 복원은 아래 B11 계약을 따른다.

## 실제 저장 공간 검사 — B14

실행의 `maxStagedBytes`는 누적 미디어 한도이며 파일시스템 여유 공간과 별개다. 서버 `automation.minimumFreeBytes`는 장치별 예비 공간을 bytes로 명시한다(256MiB~1TiB). 저장소 설정에는 2GiB를 지정한다. 필드가 없는 automation 설정은 명시적인 설정 오류이며 이전 Run의 설정·해시를 재작성하지 않는다.

`AutomationDiskSpace`는 프로젝트 dataRoot·자동 실행 root·운영체제 tmpdir의 실제 `statfs.bavail × bsize`를 BigInt로 읽는다. 폴더 identity를 검사 전후 대조하고 읽기 실패를 공간 충분으로 처리하지 않는다. 같은 장치(dev)는 예상 쓰기를 합산하고 예비 공간을 한 번만 더하며, 표본별 공간이 달라지면 작은 값을 사용한다. 서로 다른 장치는 각각 검사한다. 생성 전 예상량은 남은 미디어 한도 R에 대해 자동 실행 저장소 2R+128MiB(음성 보존·후보·Snapshot), 프로젝트 R+256MiB(자산·저장 Journal), 임시 작업 256MiB다. 이는 보수적인 운영 예상이며 실제 최종 생성량이나 디스크 예약이 아니다. 별도 APFS 볼륨이 공유하는 container, Codex 자체 내부 캐시, 외부 프로그램의 동시 쓰기까지 예약하거나 보장하지 않는다.

새 Run을 만들기 전에는 초기 Project Snapshot의 실제 바이트와 기록용 16MiB를 보존할 수 있는지 검사한다. 이 최소 공간도 없으면 Run·생성 시도를 만들지 않고 요청을 거부한다. 새 시도 등록 전과 각 실제 모델·이미지·새 음성 호출 전에 생성 여유를 검사한다. 부족하거나 통계를 읽을 수 없으면 새 호출을 시작하지 않고 원인과 필요/가용 바이트를 남긴다. 이미 받은 결과는 예비 공간 기준보다 우선 보존한다. 음성 보존 직전에는 WAV+64KiB, 후보 게시 직전에는 미디어와 실제 before/candidate JSON 바이트에 기록 여유 16MiB를 더해 확인한다. 보존 이후 프로젝트 적용 전에는 신규 미디어+256MiB와 실행 기록 16MiB 및 예비 공간을 다시 요구한다. 저장된 후보는 prepared 상태로 남아 재개 때 생성 없이 적용된다.

`AUTOMATION_DISK_SPACE_LOW`, `AUTOMATION_DISK_CHECK_FAILED`, 실제 `ENOSPC`·`EDQUOT`는 무한 재시도를 하지 않는다. 생성 중단은 interrupted와 needs-attention으로 기록하고 사용자 ‘이어 만들기’에서 다시 검사한다. 시작 전 부족은 시도 한도를 소모하지 않으며 실제 호출한 시도는 유한 한도를 유지한다. 같은 실행의 완성된 WAV를 검증해 재사용하고 이미 반영한 작업을 다시 생성하지 않는다. 실제 Commit 정산은 여유 공간 검사보다 먼저 수행한다. 저장 공간의 갑작스러운 소진으로 완성 파일을 쓰지 못했다면 재사용을 보장하지 않으며 부분 파일은 기존 저장 복구 계약대로 보존한다. 자동 삭제로 공간을 확보하지 않는다.

웹 저장 공간 표시는 선택 파일 한도로 `/automation/storage`를 조회한 시점의 결과다. 설정 변경 시 다시 조회하며 사용자도 다시 확인할 수 있다. 과거 조회 성공이 이후 실행을 허용하는 영속 플래그가 되지 않는다. 선택 백업·복원과 전체 작품 결과 검증은 이 검사와 별도의 남은 B14/A10 범위다.


## 미저장 입력과 작업 위치 복원 — B11

브라우저 임시 입력은 서버 Project·승인·자동 제작 Run과 별도로 보관한다. 프로젝트·폼·엔티티 ID를 복합 scope로 사용하고 화면 인스턴스마다 독립 writer UUID를 만든다. 각 writer는 자기 localStorage 기록만 갱신한다. 명시적 복원·선택·폐기는 다른 기록의 ID와 sequence를 대체 대상으로 남기며 원본 기록을 삭제하지 않는다. 다른 탭이 그 뒤 수정한 sequence는 다시 선택 후보가 된다. 단일 후보는 자동으로 폼에 복원하고 둘 이상은 내용을 보여 주어 사용자가 고른다. 파일 업로드의 File 객체·미디어 바이트는 보관하지 않는다.

현재 연결 범위는 컷 연출, Visual Plan, 프레임 설명·위치, 음성 시각·음량, 글자 시각·Canonical 연결, 제작 프로필, 글자 배치·읽기 기준이다. 서버 저장용 의미 검증과 임시 입력의 타입 검증을 구분해 음수 등 수정 중인 숫자도 가능한 폼에서 보존한다. 타입을 확인할 수 없는 기록·저장 공간 초과·권한 오류는 명시적으로 표시하고 원래 저장 기록을 덮지 않는다. 실패한 미저장 입력이 남으면 페이지를 떠날 때 브라우저 경고를 요청한다. 브라우저 저장소 삭제·강제 종료·저장 실패 이후 복원은 보장하지 않는다.

임시 입력에는 작성 기준 값과 Project revision을 기록한다. 작성 값이 최신 서버 값과 같아졌거나 이전 기준에서 수정하지 않았다면 새 기준을 사용한다. 수정한 값이 남은 상태에서 revision이 바뀌면 보수적으로 비교를 요구한다. 작성 값과 현재 서버 값을 표시하며 사용자가 작성 값을 현재 기준으로 검토하거나 서버 값을 선택하기 전에는 해당 폼 저장을 막는다. 기준 선택은 서버 적용·확정을 실행하지 않는다. 삭제된 컷의 임시 기록은 남겨 두며 다른 컷에 옮기지 않는다. 제작 현황의 미저장 편집 기록 보관함은 현재 Project ID와 일치하는 구조화 편집 scope만 읽는다. 다른 프로젝트·가져오기 전역 scope·생성 영수증과 복구 키는 열람 대상에서 제외한다. 현재 스키마로 변환하거나 임시 값을 적용하지 않고 당시 JSON·작성 기준을 보존해 보여 준다. 현재 대상이 있으면 해당 종류의 실제 소속 편집기로 이동하고 사라진 대상은 내용 복사·기록 JSON 보관만 제공한다. 같은 문자열 ID를 다른 엔티티 종류로 연결하지 않는다. 여러 writer는 공통 supersession 규칙으로 모두 보존하고 storage 이벤트·명시적 다시 읽기로 갱신한다. 손상된 scope는 오류로 분리해 정상 기록까지 숨기거나 원본 기록을 삭제하지 않는다. 사용자 복사·파일 보관은 서버 저장·자동 대상 지정·승인을 실행하지 않는다.

프로젝트별 작업 공간·선택 구간·컷·편집 탭·재생 위치를 기억한다. 재생 중 위치는 최대 1초 간격, 정지·탐색은 즉시 기록한다. 새로고침·새 탭에서 현재 프로젝트의 유효한 위치만 복원하고 자동 재생·Monitor 열기·생성·승인·이전 검증 결과를 재실행하지 않는다. 원본에서 사라진 ID나 영상 길이 밖의 위치는 오류를 보이고 사용자가 현재 위치를 다시 기억하도록 한다. 위치 기록은 편집 내용이 아니므로 여러 탭 중 마지막 기록을 사용한다. 미저장 입력의 여러 writer 보존과 구별한다.

문서 가져오기의 단계·연결·제작 설정·근거 기록·생성 결과와 독립 콘티의 경로·이름·임시 글자 유지 시간을 같은 브라우저 초안 계약으로 보관한다. 복원된 문서 Preview는 과거 검토 기록이며 현재 원본 확인 전에는 모델 검토·패키지 생성·불러오기를 허용하지 않는다. 원본 재확인은 현재 8개 파일의 fingerprint를 대조하고 선택한 연결로 Preview를 다시 계산한다. 변경이 있으면 입력을 보존하고 1단계에서 명시적인 새 원본 검토를 요구한다. 진행 중이던 busy·검토/생성 요청·보충 근거 재검토 예약을 복원하여 재실행하지 않는다.

독립 콘티 폼은 시작 단위의 flow ID를 보관한다. 실제 요청 직전 브라우저 Web Lock 아래 같은 flow·경로·이름·유지 시간에 결속한 UUID를 localStorage에 먼저 기록한다. 응답을 놓치거나 새로고침해도 동일 입력은 그 ID를 사용하고 서버는 creationFingerprint와 기존 Current를 대조해 후속 편집을 보존한다. 성공 기록도 삭제하지 않으며, 완료한 폼을 비우고 새로 작성한 입력은 새 flow다. 브라우저 기록 손상·저장 실패·Lock 미지원은 요청 전에 표시한다. 동일 원본 경로의 파일 자체가 바뀌면 서버 계약 충돌이며 임의로 새 ID를 만들어 통과시키지 않는다.

패키지 생성은 당시 입력·설정·출력 경로를 요청 전에 보관하며 미확인 시도들을 유지한다. `/api/document-packages/verify`는 같은 입력으로 재구성한 payload와 실제 8개 문서·설정·handoff의 전체 UTF-8 바이트, 폴더 identity를 재검사하는 읽기 전용 경로다. 완전한 일치일 때만 생성 결과를 복구한다. 누락·변경·symlink·원본 변경을 성공으로 간주하거나 파일을 덮고 지우지 않는다. 다시 불러오기도 기존 패키지 검사를 거친다. 생성 결과 복원 자체가 파일의 영속 존재나 Final 승인을 증명하지 않는다.

자동 제작 시작 폼은 프로젝트별 브라우저 scope에 모델·가이드 음성·속도·구간 선택·표현 수준·글자/음량 계획 방식·실행 한도를 함께 보관한다. 현재 서버에서 권장 설정과 최근 실행을 읽은 뒤 복원하며, 시작 폼의 입력과 현재 실행 Snapshot을 구별한다. 수정 중인 빈 음성 이름·범위 밖 숫자는 임시 타입으로 보관하고 시작 직전에 공통 AutomationSettingsSchema를 검사한다. 프로젝트 revision·시작 기준 변경과 다른 탭의 입력은 비교·선택 전까지 시작을 차단한다. 현재 원본에서 사라진 구간은 자동 제거하지 않고 재선택을 요구한다. 복원·비교·선택은 실행/재개/취소·Project 변경을 호출하지 않는다. 이미 실행 중인 Run의 진행과 중지/재개 버튼은 시작 폼과 별도로 유지한다. 브라우저는 유효한 저장 한도만 실제 공간 조회에 사용하며, 공간 조회 성공을 실행 권한으로 보관하지 않는다.

기준 이미지의 종류·대상·설명과 Source Update의 handoff 경로·임시 글자 유지 시간을 프로젝트별로 보관한다. 기준 이미지 File 객체는 복원하지 않고 대상·Project revision 변경 즉시 다시 선택하게 한다. 현재 원본에 없는 대상은 별도로 표시하고 등록을 차단한다. Source Update 검토 결과는 메모리에만 두고 경로·유지 시간·revision이 일치할 때만 적용 버튼을 활성화한다. 웹의 `/source-update/preview`는 Project ID·요청 입력·검증한 PackagePayload의 정규 JSON SHA-256을 반환하며 `/source-update/apply`는 선택 원본을 다시 읽어 동일한 근거인지 검사한 뒤 기존 ProjectStore revision/lock·Source Update 검증으로 적용한다. 원본 파일 내용 또는 handoff 의미·설정이 달라지면 `SOURCE_REVIEW_STALE` 409로 다시 검토하게 하고 저장본을 변경하지 않는다. 검토 뒤 잠금·승인·편집이 바뀐 경우에도 기존 revision·영향 검사로 거부한다. 기존 `/source-impact`와 `/source-update`는 스크립트의 명시적인 직접 교체 계약으로 유지하며 웹에서 대체 호출하지 않는다. 복원·실패 후에는 검토를 다시 실행해야 하며 등록·적용을 자동 실행하지 않는다.

독립 Placement의 정보 ID 선택·검토 메모와 검토 필요 Text Cue의 본문 근거 종류·대상을 Project·Placement/Cue별로 복원한다. revision 변경과 다른 writer는 공통 비교 규칙을 사용하며 정보성 저장·권한 확정 전에 해결한다. 원본에서 사라진 선택은 보존하여 표시하고 연결을 차단한다. 누락 정보는 사용자가 선택 해제하고, 본문 근거는 새 유효 대상을 명시적으로 고른다. 첫 후보를 대신 선택하지 않는다. 본문 근거 종류 변경도 대상 선택을 다시 요구한다. 원본 교체로 컷이 바뀌어도 같은 Placement/Cue의 임시 기록은 새 컷에서 검토할 수 있으며, 임시 입력 복원이 정보성·권한·시각 승인 API를 실행하지 않는다.

검토·전달 패키지 입력은 Project별 scope에 저장한다. 입력 기준은 revision과 정규화한 출력 옵션이며 객체 키의 저장 순서 차이는 변경으로 취급하지 않는다. 실제 기준 변경·다른 탭 충돌은 비교 뒤 사용한다. 생성 결과는 별도 scope의 생성 당시 경로·revision·시각·파일 크기/해시 기록으로 복원하며 현재 파일 무결성이나 Final 상태로 표시하지 않는다. 생성 허용 미리보기는 메모리에만 두고 새로고침·입력 변경 후 서버의 현재 원본·설정 검사를 다시 요구한다. 입력/기록 복원과 기준 선택은 서버 생성·승인을 실행하지 않는다. 검토 패키지 생성 전 UUID·무작위 256-bit 복구 키·입력·미리보기 basis·출력 경로·시도 시각을 별도 브라우저 scope에 보관하고 보관 검증 실패 시 전송하지 않는다. 모든 생성 시도를 유지하며 새로고침은 자동 재전송·생성·복구를 하지 않는다. 명시적인 `/api/projects/:projectId/review-bundles/verify`는 게시된 manifest의 HMAC-SHA256 인증 코드, 요청·입력·프로젝트 hash 결속, 완전한 파일 목록·크기·SHA-256, 경로·폴더 identity를 검사해 생성 당시 결과를 복구한다. 복구 키·절대경로·원문 입력은 인증 metadata에 넣지 않는다. 키는 브라우저에만 남고 생성 응답이나 패키지에 저장하지 않는다. 검증은 원본 저장소·현재 revision·현재 Build를 읽거나 수정하지 않으므로 후속 편집과 서버 재시작 뒤에도 과거 결과를 복구할 수 있다. 복구는 현재 Final 승인 증명이 아니다. 미게시·불완전 파일·변조된 manifest/파일·다른 요청·추가 파일·symlink는 성공으로 처리하지 않고 보존한다. 웹 게시물은 기본 11개 파일과 선택 미디어를 포함해 512 MiB·20,000개 파일, manifest 4 MiB 이내에서 생성·검증하며 기존 미디어 256 MiB 제한을 유지한다. 인증 기록이 없는 이전 패키지와 브라우저 복구 키를 잃은 경우는 자동 복구하지 않는다.

문서 모델 검토는 가져오기 flow별로 요청을 전송하기 전에 UUID·당시 입력·수정한 필드·폼 반영 여부를 보관한다. 브라우저 보관을 확인하지 못하면 전송하지 않는다. 새로고침만으로 검토 생성·취소·결과 적용을 재실행하지 않는다. 원본 재확인 후 명시적으로 같은 요청에 다시 연결하고 서버 상태를 읽는다. 실행 중이면 같은 ID를 관찰하며, 완료 결과는 저장된 입력과 현재 파일을 서버에서 다시 검증한 뒤 빈 입력에 병합한다. 제작 설정을 수정했다가 비운 이력도 보호하고 연결·프리셋·원본 변경은 재검토를 요구한다. 이미 반영한 요청은 결과 근거만 다시 표시하며 현재 입력·확인 상태를 덮지 않는다. 다른 flow의 응답은 반영하지 않고, 여러 탭의 기록 충돌은 공통 초안 선택 규칙을 적용한다. 서버 종료로 실패한 요청은 실패를 표시하며 새 실행으로 가장하지 않는다. 첫 응답 유실 뒤에도 보관한 ID를 GET으로 조회한다. 미접수 또는 통신 오류에서는 명시적인 같은 요청 재전송을 제공한다. `POST /api/document-reviews/:id/start`는 같은 ID·입력의 running/completed/failed/cancelled 상태를 재사용하고 새 모델 실행을 만들지 않는다. 다른 입력은 409 `DOCUMENT_REVIEW_ID_CONFLICT`, 상태 없이 입력/사본만 남은 불완전 접수는 request 범위 423 `DOCUMENT_REVIEW_START_INCOMPLETE`로 파일을 보존한다. 다른 ID의 실행과 경쟁하면 409 Busy이며 자동 새 ID를 만들지 않는다. 반환된 기록의 입력·원본 사본·해시 결속을 검사하고 기존 ID 없는 POST 계약은 유지한다. 삭제된 대상의 임시 편집 기록도 위 보관함에서 확인한다. 기존 완료 미리보기나 파일 선택을 영속 권한으로 취급하지 않고 재조회하는 계약이 필요하다. B11 전체 완료로 판정하지 않는다.


## 선택 발화의 자동 재생성

`POST /api/projects/:projectId/automation/speech-retakes`는 현재 revision, 한 Cue, 설치 음성 이름·속도, 종료 허용 시각과 실행 한도를 받는다. 시작 시 원문 Unit·현재 Cue·기존 Asset을 해시로 결속한 `purpose: speech-retake`를 Run에 저장한다. 이 Run은 그 작업 하나를 합성·검사·반영한 뒤 검토 대기로 끝난다. 전역 설정·컷·그림·다른 발화 계획으로 확장하지 않는다. 이전 Run에는 purpose를 추가하지 않으며 기존 settingsHash를 유지한다. 새 Run의 설정 해시는 재생성 의도까지 포함한다.

화면의 「발화 선택 생성·비교」에서 실제 설치 목록을 선택한다. 기존 자동 합성 기록의 실제 목소리·속도는 초기 입력에 표시하며 외부 WAV의 목소리는 추측하지 않는다. 입력은 Cue별 브라우저 초안으로 복원하되 실행을 다시 시작하지 않는다. 상태 조회·중지·같은 설정으로 재개·취소는 일반 자동 제작 저장소를 사용한다. 초기 UI 실행 한도는 5분·64MB·작업 1개다. 설정을 바꿀 때는 이전 실행을 취소하고 새 실행을 시작한다. 수동 Codex 대기 요청은 별도 버튼으로 표시한다.

실제 로컬 음성 엔진만 호출하고 모델·이미지 엔진을 호출하지 않는다. 기존 시작 시각·구간 관계·원문을 유지하고 새 WAV의 실측 길이로 종료를 정한다. 명시한 종료 한도, 같은 화자의 중복 재생 확대, 컷 확정·잠금, 현재 Cue·전체 후보의 구조·정보 공개 문제를 검사한다. 그림은 그대로 보존하고 새 공개 문제를 차단하므로 그림 승인만으로 명시적 발화 재생성을 금지하지 않는다. 다른 자동 작업의 보호 정책은 유지한다. 실제 이전 WAV도 합성 전후 읽어 검사한다. 자동 음량의 기존 수치는 보존하되 계획 근거를 비워 새 음량 검토를 요청한다. 수동 음량은 유지하고 페이드가 새 길이를 넘으면 차단한다.

허용 길이를 넘은 WAV는 실행 캐시에 보존하며 기존 콘티는 변경하지 않는다. 재개는 같은 설정의 캐시를 사용하며 음성을 늘이거나 자르지 않는다. 새 Asset ID·경로·버전과 생성 기록을 추가하고 이전 파일·기록은 보존한다. 원자 적용·게시 후 정산·중단 재개는 기존 실행기를 사용한다. 완료 후 새 음원을 불러와 현재 음원과 보존된 이전 버전을 각각 들을 수 있다. 이전 버전 청취는 원본 음량을 사용하며 현재 타임라인 자산 선택을 바꾸지 않는다. 청취 검토나 전체 Final 승인으로 자동 표시하지 않는다.

### 선택 발화의 발음 보완

재생성 입력의 선택 항목 `pronunciation`은 원문 표현·등장 회차·읽을 표기 목록이다. 최대 16개, 표현/표기 각각 128 UTF-16 코드 단위 이내에서 원문에 있는 정확한 등장만 대체한다. 원문 기준으로 먼저 범위를 구하고 겹침·누락·삭제·동일 표기·잘못된 문자·macOS 제어 구문을 거부한다. 합친 낭독문도 64KiB와 제어 구문을 다시 검사한다. 일반 자동 제작에서는 원문 그대로 합성하고 발음 보완은 선택한 발화에만 적용한다. 전역/다국어 사전이나 대사 재작성은 포함하지 않는다.

화면은 원문과 전체 낭독문을 나란히 제공하고 유효하지 않은 보완 입력에서는 시작을 막는다. 보완 입력은 기존 Cue별 초안과 충돌 검사로 복원하며 새 실행을 만들지 않는다. 현재 자산의 보완 생성 기록을 읽어 다음 재생성 입력으로 제공한다. 원문이 달라지면 과거 원문·보완을 보존해 보여 주고, 현재 원문에서 재검토를 명시하거나 보완을 제거한 뒤 진행한다. 재검토 선택은 확인한 현재 원문에 결속하며 다시 바뀐 원문에는 재사용하지 않는다. 모든 보완을 제거하면 원문 낭독으로 새로 생성한다.

실제 엔진 입력·반환 결과·Run 캐시·최종 적용은 보완 목록과 낭독문 SHA-256을 대조한다. 원문 hash는 별도로 유지한다. 변경된 보완은 기존 캐시 키와 다르고 같은 Run 재개는 완성된 보완 WAV를 그대로 재검증한다. 일반 생성 기록은 보완 결과를 받을 수 없다. 보완이 있는 새 기록만 `automatic-speech-retake-1.1.0`으로 원문·낭독문·변경 목록·두 hash·실제 WAV를 보존한다. 이전 무보완 결과와 Run의 hash·캐시·Project Schema 1.17은 변경하지 않는다. 출력 대본·자막은 원문을 사용하며 청취·의미 일치 검토나 Final 승인을 대신하지 않는다.

## 저장 완료한 콘티의 선택 백업

B14의 선택 백업은 `cutroom-project-backup` 1.0.0 / `committed-project-history` 계약이다. 선택한 하나의 콘티에서 현재 project.json, 0부터 현재 revision까지의 모든 Version, 각 Version이 등록한 전체 자산의 실제 파일을 원래 바이트로 보관한다. 스키마 이관은 메모리 검사에만 사용한다. 저장된 sources·Dataset·handoff·제작 설정·생성 기록·승인은 모두 원본 JSON에 포함해 유지한다. 외부 제작 문서 폴더, Run 이벤트·생성 캐시·요청 대기열, 브라우저 미저장 입력·복구 키는 포함하지 않는다. 저장 상태 백업과 작업 환경 전체 백업을 구분한다.

웹의 제작 현황에서 기존 상위 폴더와 아직 없는 새 이름을 입력한다. `/backups/preview`는 Project revision, 원래 파일별 SHA-256·크기, 실제 출력 경로와 상위 폴더 identity를 기준 해시로 묶는다. `/backups`는 같은 내용을 다시 읽고 일치할 때만 기존 Claim/Publisher의 staging과 원자 게시를 사용한다. 원본에 잠금·heartbeat·복구 파일을 쓰지 않는다. 해당 Project의 저장 Lock·Transaction·복구 검토·미래/누락/불일치 Version은 백업 게시를 차단한다. 생성 중이어도 마지막 Commit이 안정적이면 저장 완료 부분만 보관할 수 있으며 Run 재개 가능성을 보장하지 않는다. 원본 ID를 읽지 못해 unknown으로 기록한 복구 표시도 스키마·파일명·directoryName·unknown:key가 모두 같은 다른 폴더를 가리키면 해당 폴더에만 적용한다. 표시를 삭제하거나 복구된 것으로 만들지 않는다. 현재 폴더의 표시와 위치를 증명하지 못하는 표시·격리된 잘못된 표시는 계속 차단한다. 검토 패키지와 백업은 이 저장 범위 판정을 공유한다.

파일 20,000개, 전체 payload 512MiB, 개별 JSON 32MiB 이내에서 고정 크기 읽기를 사용한다. 출력 예상량과 256MiB 예비 공간을 실제 디스크에서 검사하고 게시 직전에도 여유를 다시 확인한다. 기존 감사용 Asset·Version을 삭제해 공간을 만들지 않는다. 경로 이탈·symlink·누락 파일·중복/추가 파일·해시/크기 변경을 거부한다. Manifest는 파일 동일성 검증용이며 외부 작성자의 신원 서명은 아니다.

기존 손상된 미디어 파일이 존재하면 metadata를 고치거나 오류를 숨기지 않고 그 바이트를 보관한다. 백업 Manifest의 파일 해시는 Asset metadata의 기대 해시와 다른 개념이다. 검증은 파일 보관과 Version 일치를 뜻하며 그림·음성 정상성이나 Final을 의미하지 않는다. 복원 뒤 ProjectStore의 실제 미디어·Final 검사를 그대로 적용한다. 누락 파일이 있으면 완전한 백업으로 게시하지 않는다.

브라우저는 저장 위치 초안을 보관하고 revision·다른 writer 충돌을 확인한다. 생성 전 검증할 출력 경로를 저장하며 응답 유실 뒤 자동 재전송하지 않는다. `/backups/verify`는 사용자가 지정한 백업의 Manifest와 전체 파일 및 Project ID를 다시 검사한다. 새로고침은 검증·생성·승인을 실행하지 않는다.

복원 CLI는 검증한 Manifest 해시를 명시적으로 받고 원래 Project ID·revision을 별도의 아직 없는 dataRoot로 복원한다. 기존 dataRoot에 병합하거나 현재 콘티를 되돌리지 않는다. 자산·Version 파일과 빈 운영 폴더를 staging에서 만든 뒤 한 번 게시한다. 복원된 저장소는 일반 ProjectStore로 열고 다음 revision으로 편집할 수 있다. 앱 설정 자동 교체·Run 재시작·브라우저 복원 UI는 이 경로에 포함하지 않는다.
