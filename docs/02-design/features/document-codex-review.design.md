# 문서 연결·설정 Codex 검토 — Design

근거: [Plan](../../01-plan/features/document-codex-review.plan.md). 기존 문서 파서·후보 검증·패키지 생성을 재사용한다.

## 실행과 격리

`documentReview` 서버 설정에 설치된 Codex App 실행 파일, 검토 저장 루트, 제한 시간을 명시한다. 설정이 없는 기존 서버는 수동 가져오기를 유지하며 자동 검토를 미설정으로 표시한다. 로컬 stdio app-server를 실행하고 `initialize → account/read → config/read → thread/start → turn/start`를 호출한다. 계정 유형은 ChatGPT여야 한다. 모델은 사용자 설정을 상속하고 실제 응답 모델을 기록한다.

각 검토는 빈 임시 작업 디렉터리와 ephemeral thread를 사용한다. read-only·승인 없음, 환경 접근·MCP 서버·앱·플러그인·훅·셸·다중 에이전트·웹 검색을 비활성화하고 검증된 8개 스냅샷만 입력으로 전달한다. 지원하지 않는 실행 파일·인증·프로토콜은 구체적 오류이며 다른 실행 경로나 API로 전환하지 않는다. 정상 종료·실패·취소·시간 초과 때 자식 프로세스와 임시 폴더를 정리한다. 서버 자체 도구 요청은 거부한다.

## 검토 계약

- 기준: 정규 입력 폴더 경로, 8개 파일 fingerprint, 사용자의 연결·설정, 선택 프리셋. 요청마다 UUID와 기준 해시를 기록한다.
- 결과: 요약과 항목별 field/key/value, origin(document/inference/recommendation/unresolved), reason, evidence(fileId/locator/quote).
- 문서 확인은 기존 파서의 유일한 자동 연결로 증명되는 값만 허용한다. 모델의 새 연결은 inference이며 사용자가 확인한다. 확률 점수로 확정하지 않는다.
- 근거는 선택한 스냅샷의 실제 line 또는 JSON pointer에서 찾은 인용문이어야 한다. 연결은 현재 후보와 일치하고 인물·장면은 중복될 수 없다. 장면 제안 적용 후 원문 구간 후보를 다시 검사한다.
- 추천 설정은 지원 FPS·샘플레이트·화면비·타임코드 계약을 통과해야 한다. 프리셋은 서버에 명시적으로 저장·선택하며 모델이 만든 문서 사실로 표시하지 않는다.
- 생성 패키지 설정 1.1.0에 최종 항목별 출처·근거·요청·실제 모델·확인 상태를 보존한다. 기존 1.0.0을 그대로 읽으며 저장본을 재작성하지 않는다. 미확정 제안·값과 맞지 않는 감사 정보는 생성 전에 차단한다.

## 서비스와 API

프로젝트 저장소와 별도인 문서 검토 저장소를 사용한다. 읽은 요청 스냅샷은 불변이며 상태는 실행/완료/실패/취소/만료로 구분한다. 한 서버에서 하나의 검토만 실행하며 진행 중인 같은 기준의 중복 실행은 재사용한다. 종료된 요청의 재시도는 새 UUID로 기록한다. 다른 검토는 busy로 알린다. 프로세스 소유권이 없는 실행 상태는 재시작 때 중단으로 기록한다. 외부 생성 중 기존 프로젝트 lock을 잡지 않는다.

`GET /api/document-reviews/status`, `POST /api/document-reviews`, `GET /api/document-reviews/:id`, `POST /api/document-reviews/:id/cancel`, `POST /api/document-reviews/:id/validate`와 프리셋 목록/저장 API를 제공한다. 완료 뒤에도 validate에서 원본 fingerprint를 다시 검사하고 변경됐으면 적용하지 않는다. 요청·응답 크기와 실행 시간을 제한한다.

## 폼 적용과 사용자 검토

연결·설정 단계에 검토 버튼·진행 상태·취소·오류·재시도·근거 목록을 둔다. 결과가 도착해도 현재 폼의 사용자 수정은 유지한다. 원본이나 기준 연결이 바뀌었으면 자동 반영을 중단하고 새 검토를 안내한다. 빈 값과 동일한 이전 제안만 채우며 추론·추천에 확인 필요 표시를 붙인다. 사용자 변경은 해당 항목을 사용자 지정으로 바꾼다. 제안을 확인하는 명시적 동작 뒤에만 다음 단계로 간다. 프리셋은 사용자가 저장·선택해야 재사용한다.

## 검증

순수 검증·적용 함수는 잘못된 출처와 후보, 중복·필수 결과 누락, 사용자 수정과 원본 변경, 확인 상태·패키지 재읽기를 검사한다. API는 실제 자식 프로세스 프로토콜 대역으로 오류·타임아웃·중복·취소·종료·재시작을 검사하고, E2E는 버튼→진행→입력·근거→확인→패키지까지 수행한다. 실제 설치된 엔진에서 ChatGPT 인증 및 JSON 완료 응답을 확인한 뒤 실제 8개 제작 문서와 독립 합성 자료로 동작을 확인한다.

공식 프로토콜: [Codex App Server](https://learn.chatgpt.com/docs/app-server). 설치 엔진 0.153.4의 생성 TypeScript 스키마와 작은 실제 JSON 응답으로 연결을 확인했다.
