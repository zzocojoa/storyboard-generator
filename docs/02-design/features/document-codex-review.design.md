# 문서 연결·설정 Codex 검토 — Design

근거: [Plan](../../01-plan/features/document-codex-review.plan.md). 기존 문서 파서·후보 검증·패키지 생성을 재사용한다.

## 실행과 격리

`documentReview` 서버 설정에 설치된 Codex App 실행 파일, 검토 저장 루트, 제한 시간을 명시한다. 설정이 없는 기존 서버는 수동 가져오기를 유지하며 자동 검토를 미설정으로 표시한다. 로컬 stdio app-server를 실행하고 `initialize → account/read → config/read → thread/start → turn/start`를 호출한다. 계정 유형은 ChatGPT여야 한다. 모델은 사용자 설정을 상속하고 실제 응답 모델을 기록한다.

각 검토는 빈 임시 작업 디렉터리와 ephemeral thread를 사용한다. read-only·승인 없음, 환경 접근·MCP 서버·앱·플러그인·훅·셸·다중 에이전트·웹 검색을 비활성화하고 검증된 8개 스냅샷과 선택한 보충 인물표의 검증된 대응만 입력으로 전달한다. 지원하지 않는 실행 파일·인증·프로토콜은 구체적 오류이며 다른 실행 경로나 API로 전환하지 않는다. 정상 종료·실패·취소·시간 초과 때 자식 프로세스와 임시 폴더를 정리한다. 서버 자체 도구 요청은 거부한다.

## 검토 계약

- 기준: 정규 입력 폴더 경로, 8개 파일 fingerprint, 사용자의 연결·설정, 선택 프리셋. 요청마다 UUID와 기준 해시를 기록한다.
- 결과: 요약과 항목별 field/key/value, origin(document/inference/recommendation/unresolved), reason, evidence(fileId/locator/quote).
- 문서 확인은 기존 파서의 유일한 자동 연결로 증명되는 값만 허용한다. 모델의 새 연결은 inference이며 사용자가 확인한다. 확률 점수로 확정하지 않는다.
- 근거는 선택한 스냅샷의 실제 line 또는 JSON pointer에서 찾은 인용문이어야 한다. 연결은 현재 후보와 일치하고 인물·장면은 중복될 수 없다. 장면 제안 적용 후 원문 구간 후보를 다시 검사한다.
- 추천 설정은 지원 FPS·샘플레이트·화면비·타임코드 계약을 통과해야 한다. 프리셋은 서버에 명시적으로 저장·선택하며 모델이 만든 문서 사실로 표시하지 않는다.
- 생성 패키지 설정 1.1.0에 최종 항목별 출처·근거·요청·실제 모델·확인 상태를 보존한다. 보충 근거는 설정 1.2.0의 identityEvidence와 identity-document 출처에 보존하며 기존 1.0.0·1.1.0을 그대로 읽으며 저장본을 재작성하지 않는다. 미확정 제안·값과 맞지 않는 감사 정보는 생성 전에 차단한다.

## 서비스와 API

프로젝트 저장소와 별도인 문서 검토 저장소를 사용한다. 읽은 요청 스냅샷은 불변이며 상태는 실행/완료/실패/취소/만료로 구분한다. 한 서버에서 하나의 검토만 실행하며 진행 중인 같은 기준의 중복 실행은 재사용한다. 종료된 요청의 재시도는 새 UUID로 기록한다. 다른 검토는 busy로 알린다. 프로세스 소유권이 없는 실행 상태는 재시작 때 중단으로 기록한다. 외부 생성 중 기존 프로젝트 lock을 잡지 않는다.

`GET /api/document-reviews/status`, `POST /api/document-reviews`, `POST /api/document-reviews/:id/start`, `GET /api/document-reviews/:id`, `POST /api/document-reviews/:id/cancel`, `POST /api/document-reviews/:id/validate`와 프리셋 목록/저장 API를 제공한다. 완료 뒤에도 validate에서 원본 fingerprint를 다시 검사하고 변경됐으면 적용하지 않는다. 요청·응답 크기와 실행 시간을 제한한다. 웹의 접수 전 ID 보관·동일 요청 재전송·새로고침 복원 계약은 [자동 제작 Design의 B11](storyboard-automation.design.md)을 따른다.

## 폼 적용과 사용자 검토

연결·설정 단계에 검토 버튼·진행 상태·취소·오류·재시도·근거 목록을 둔다. 결과가 도착해도 현재 폼의 사용자 수정은 유지한다. 원본이나 기준 연결이 바뀌었으면 자동 반영을 중단하고 새 검토를 안내한다. 빈 값과 동일한 이전 제안만 채우며 추론·추천에 확인 필요 표시를 붙인다. 사용자 변경은 해당 항목을 사용자 지정으로 바꾼다. 제안을 확인하는 명시적 동작 뒤에만 다음 단계로 간다. 프리셋은 사용자가 저장·선택해야 재사용한다.

## 검증

순수 검증·적용 함수는 잘못된 출처와 후보, 중복·필수 결과 누락, 사용자 수정과 원본 변경, 확인 상태·패키지 재읽기를 검사한다. API는 실제 자식 프로세스 프로토콜 대역으로 오류·타임아웃·중복·취소·종료·재시작을 검사하고, E2E는 버튼→진행→입력·근거→확인→패키지까지 수행한다. 실제 설치된 엔진에서 ChatGPT 인증 및 JSON 완료 응답을 확인한 뒤 실제 8개 제작 문서와 독립 합성 자료로 동작을 확인한다.

공식 프로토콜: [Codex App Server](https://learn.chatgpt.com/docs/app-server). 설치 엔진 0.153.4의 생성 TypeScript 스키마와 작은 실제 JSON 응답으로 연결을 확인했다.

## 미해결 인물 근거 보완

`production-characters-v1`는 사용자가 명시한 인물 원본과 production-footprint 1.0.0만 읽는다. 기본 8개 문서 입력은 유지한다. 별도 `/api/document-identities/preview`·`validate`에서 같은 프로젝트 ID, 8개 문서 fingerprint, manifest→footprint→characters 정규 JSON SHA-256, 이름·ID 유일성, 후보 적합성, 기존 연결과 충돌을 검사한다. 읽기는 일반 파일·256KB·UTF-8·파일 동일성을 검사한다. 문서 안의 경로는 탐색하지 않는다. JSON 원본의 부가 필드는 해시와 보존 대상이며 모델에 제공하는 대응은 이름·ID·출처로 제한한다.

미리보기는 현재값과 목표값을 보여 준다. 적용 전 원본을 다시 읽어 스냅샷의 바이트 해시까지 비교하며, 브라우저는 당시 폴더·문서 fingerprint·연결·보충 경로와 현재 입력이 같은지 검사한다. 적용은 빈 연결만 바꾸고 나머지 입력과 확인 기록을 보존한다. 적용 뒤 Codex 검토에는 검증된 대응과 현재 입력을 전달한다. 명시적 인물표 연결의 증명은 모델이 아닌 서버 코드의 책임이다.

연결 단계 상단의 최종 인물 연결은 현재 입력과 공통 mappingProblems에서 계산한다. 중복·후보 이탈은 연결 검토, 미확정 추론은 선택 ID와 확인 동작, 미연결은 결정 보류와 보충 자료 또는 직접 선택 동작으로 표시한다. 인물 항목이 없는 경우에만 인물 연결 대상 없음을 표시하며 근거 부족을 연결 불필요로 바꾸지 않는다. 자동 연결 버튼은 기존 preview→validate→apply 흐름을 연속 실행한다. 두 호출 사이 파일 변경·입력 변경·기존 연결 충돌은 적용을 차단한다. 성공 시 최종 대응표로 이동하며, 별도 미리보기 후 적용 흐름도 유지한다.

`/api/document-identities/saved/preview`는 문서 검토 저장소의 completed 기록 중 현재 8개 파일 fingerprint와 일치하는 검증된 인물 원본 사본을 찾는다. 모델의 과거 추론은 재사용하지 않는다. 요청 입력과 완료 기록의 basisHash를 대조하고 현재 문서를 대상으로 manifest→footprint→characters 사슬과 후보·현재 연결 충돌을 다시 검사한다. 화면은 빈칸에 적용할 ID를 먼저 보여 주며 사용자가 자동 선택을 누르면 `/saved/validate`로 지정 reviewId와 현재 문서를 재확인한다. 바뀐 폼 기준의 비동기 결과는 반영하지 않는다. 기존 검토 기록은 재작성하지 않고 적용된 근거는 같은 identityEvidence·identity-document 계약에 보존한다. 처음 보는 문서나 변경된 문서에는 저장 근거가 없다고 구분하며 외부 폴더를 탐색하지 않는다.

설정 1.2.0은 identityEvidence 안에 두 파일의 원문 사본·바이트 해시·프로젝트·문서 fingerprint를 보존한다. 별도 출력 파일 수는 늘리지 않는다. identity-document 감사 항목은 이름·ID·JSON pointer와 정확히 결속하며 패키지 생성·가져오기에서 전체 사슬과 충돌을 다시 검사한다. 원본 외부 파일 없이 재읽기가 가능하며, 설정 1.0.0·1.1.0에 근거 필드를 끼워 넣을 수 없다. 기존 출처를 무근거 보충 출처로 승격하지 않는다.

미해결 사유는 인물 입력 옆에 표시하고 필요한 자료를 안내한다. 다른 제안들을 확인해도 미해결 항목이 남으면 근거 영역을 펼친다. 제작 설정 입력 상태와 남은 연결 수는 별도로 안내한다. 보충 근거 해제는 해당 출처로 채운 연결만 해제하고 사용자 수정은 유지한다. 원본 변경·다른 이야기 입력은 보충 상태를 초기화하며, 생성 후 수정은 기존 단계 이동 계약에 따라 새 패키지 버전으로 저장한다.
