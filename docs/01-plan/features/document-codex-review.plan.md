# 문서 연결·설정 Codex 검토 — Plan

## 목적과 범위

제작 문서 8개를 검토한 뒤 Codex App의 로컬 실행 엔진으로 연결·제작 설정 초안을 만들고 가져오기 폼에 반영한다. 사용자는 내부 ID와 기술 설정을 처음부터 직접 채우지 않고 근거와 미해결 항목을 검토한다. 지원하는 모든 `production-documents-v1` 스토리에 같은 로직을 적용한다.

## 요구사항과 완료 기준

1. 웹 버튼에서 실제 Codex 검토를 시작하고 진행·완료·실패·취소 상태와 재시도를 제공한다. 요청만 저장하고 별도 채팅 입력을 요구하는 흐름으로 완료하지 않는다. ChatGPT 로그인과 설치된 Codex App 엔진을 사용하며 API 키·SDK·다른 제공자로 전환하지 않는다.
2. 입력은 8개 문서의 검증된 스냅샷, 후보와 근거, 현재 폼 값, 사용자가 선택한 제작 프리셋이다. 원본 폴더를 수정하거나 문서의 명령·외부 경로를 실행하지 않는다.
3. 연결 결과를 문서 확인·Codex 추론·미해결로 구분한다. 문서의 명시적 대응만 자동 확정하고 추론은 확인이 필요한 제안으로 입력한다. 존재하지 않는 ID, 중복 연결, 잘못된 출처와 설정을 거부한다.
4. 제작 설정은 사용자가 저장·선택한 프리셋을 우선한다. 없는 값은 근거와 함께 추천하며 문서의 사실로 표시하지 않는다. 저장한 프리셋은 다른 스토리에서도 명시적으로 선택해 재사용한다.
5. 자동 입력은 빈 값과 변경되지 않은 기존 Codex 제안만 대상으로 한다. 검토 중·후 사용자 편집을 덮지 않는다. 문서 fingerprint와 입력 기준이 달라진 결과는 자동 적용하지 않는다.
6. 적용한 값의 출처·근거·확인 상태를 UI와 생성 패키지에 보존한다. 추론·추천을 확인한 뒤 패키지 생성으로 진행한다. 기존 수동 가져오기와 이전 패키지는 호환된다.
7. 요청은 프로젝트 생성 전 문서 검토 상태로 분리한다. 제한된 동시 실행·응답 크기·시간, 실패 원인, 서버 종료 및 재시작 시 중단 상태를 다룬다. 기존 콘티·생성 기록은 변경하지 않는다.
8. 독립된 두 문서 묶음, 잘못된 결과·출처, 중복 클릭, 원본 변경, 사용자 편집 경쟁, 취소·실패·재시도, 프리셋 저장·선택과 패키지 재읽기를 검사한다. 실제 Codex 엔진과 브라우저에서 끝까지 확인한다.

## 진행 순서

로컬 엔진 연결 검증 → 요청·결과·출처 계약 → 문서 검토 실행 서비스와 API → 자동 입력·근거 검토 UI 및 프리셋 → 자동 검사·실제 문서 검토·브라우저 검증 순서로 진행한다.

## 검증 경계

인물 이름과 ID를 8개 문서만으로 구분할 수 없는 경우는 정상적인 미해결 결과다. 임의 배정으로 성공률을 높이지 않는다. 현재 화면의 제작 설정만 다루며 컷·그림·음성 생성과 최종 콘티 승인은 이 기능의 범위가 아니다.
