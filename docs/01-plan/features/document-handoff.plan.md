# 제작 문서 입력 패키지 생성 — Plan

## 목적과 범위

제작 문서 8개와 사용자가 지정한 제작 설정에서 `storyboard_handoff.json`을 생성한다. 기존 상위 구조화 파일 7개, OpenAI API 키, 외부 제작 저장소 실행은 요구하지 않는다. 기존 콘티 가져오기·편집 흐름으로 연결한다. 새 브랜치는 `codex/document-handoff`다.

지원 입력은 현재 첨부된 한국어 제작 문서 형식의 명시적 계약 `production-documents-v1`이다. 임의 Markdown이나 PDF 추론은 범위 밖이다. 파일명은 이 계약 안에서만 해석하며 작품 ID·인물·장면 수·모드를 고정하지 않는다. 패널·내레이션·자막 내용이 없는 문서도 해당 요소가 없는 프로젝트에서 허용한다.

## 요구사항과 완료 조건

| ID | 요구사항 | 검증 근거 |
|---|---|---|
| DH-01 | 새 브랜치에서 Plan·Design 후 구현 | Git와 설계 문서 |
| DH-02 | 정확히 지정된 8개 원본만 읽고 내용·해시·출처를 보존 | 상위 원본이 없는 격리 폴더 테스트 |
| DH-03 | 편집표 시간, 방송 순서, 모든 발화·지문·화면 문구·음향, 촬영 지시를 추출 | 실제 전체 자료의 순서·원문 대조 |
| DH-04 | ID 대응은 명시 정보·유일한 원문 일치 또는 사용자 결정만 사용 | 중복·불일치·모호한 연결 테스트 |

| DH-07 | CLI와 웹에서 검토·설정·생성·기존 가져오기 가능 | 실제 CLI, API, E2E |

| DH-09 | 구성과 길이가 다른 독립 합성 프로젝트도 처리 | 패널 없는 별도 사례 |
| DH-10 | 검증·한계와 사용법 기록 | check·e2e 및 Check/Report |

## 위험과 대응

사람용 대본에는 Canonical ID가 없다. Unit에는 문서 위치에 기반한 새 ID를 발급하고 원본 ID처럼 표시하지 않는다. 인물 표의 행 순서로 manifest ID를 배정하지 않는다. 원문 간 차이는 숨기거나 고치지 않고 정확한 위치와 두 값을 보고한다. 자막 종료는 미정으로 보존한다. 문서에 없는 fact/clue 연결이나 상위 footprint 검증을 수행했다고 주장하지 않는다.

PDCA 스킬을 읽어 적용했으나 전용 bkit MCP 도구는 현재 세션에서 제공되지 않는다. 단계 상태는 실제 문서·구현·실행 증거로 기록하며 MCP 등록을 주장하지 않는다.
