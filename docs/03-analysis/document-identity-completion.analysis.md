# 미해결 인물 연결 완료 경로 검토

검토일: 2026-09-10. 대상은 `http://127.0.0.1:4317/`의 연결·설정 화면과 실제 Codex 요청 결과다. 아래 내용은 구현 승인 전의 검토 결과다. 승인된 보완 기능의 현재 구현·실행 결과는 [완료 검증](../04-report/document-identity-completion.report.md)을 참조한다.

## 판정

자동 검토의 보류 결과는 폼에 정확히 반영됐다. 그러나 부족한 근거를 보충하여 최종 연결로 이어가는 제품 기능은 없다. 단계를 자유롭게 이동하는 기능은 이 문제를 해결하지 않는다.

실제 요청 `519b7903-e880-423c-9805-76919e4f9802`는 completed이며 인물 2명과 제작 설정 4개를 제안했다. 백기철·윤서진·오민주는 value=null, origin=unresolved다. 앞선 요청 `f8cd1aae-30c0-4ae5-abfb-db9cb43e9611`도 같은 세 명을 보류했다. 현재 화면에서도 인물 2명·제작 설정 4개는 확인됐고 세 이름은 미지정이다. 결과 적용 실패나 검토 시간 초과의 증거는 없다.

## 발견 사항

1. **추가 근거를 받을 계약과 조작이 없다.** [review-context.ts](../../src/documents/review-context.ts)는 8개 스냅샷만 전달하고 외부 자료·과거 대화 사용을 금지한다. [review-input.ts](../../src/documents/review-input.ts)에는 추가 인물표나 보충 답변 필드가 없다. [review-model.ts](../../src/documents/review-model.ts)의 결과도 값·사유·인용만 반환하며 필요한 추가 정보·해결 상태를 표현하지 못한다. 현재 재검토 버튼은 동일한 근거를 다시 보내므로 구분 정보가 새로 생기지 않는다. 이는 CUTROOM이 설정한 실행 계약이며 Codex App 자체가 인물표를 읽을 수 없다는 뜻이 아니다.
2. **미해결 사유가 입력 항목과 분리되고 접힌다.** [DocumentReviewPanel.tsx](../../web/src/DocumentReviewPanel.tsx:38)는 미확인 제안 수로 상세 영역을 펼친다. 여섯 제안을 확인하면 미해결 세 명이 남아도 상세 영역은 접힌다. [DocumentImportFields.tsx](../../web/src/DocumentImportFields.tsx:25)의 인물 행은 미해결 사유를 받지 않아 일반적인 연결 선택 오류만 보여 준다. 부족한 정보와 다음 행동을 해당 인물 옆에 계속 보여 줄 필요가 있다.
3. **앞서 수행한 수동 보완의 근거가 자동 검토로 재사용되지 않는다.** [document-review-state.ts](../../web/src/document-review-state.ts:41)는 수동 입력을 일반 사용자 지정으로 기록한다. 추가 인물표의 프로젝트·버전·해시·필드 근거를 패키지에 묶는 경로는 없다. 이전 수동 해결은 특정 패키지를 완성한 작업이며 범용 자동 연결 기능의 구현 증거가 아니다.
4. **완료된 제작 설정에도 미완료 안내가 남는다.** [DocumentImportPanel.tsx](../../web/src/DocumentImportPanel.tsx:242)의 2단계 하단 문구는 설정의 실제 유효성과 확인 여부에 관계없이 제작 설정을 지정하라고 표시한다. 현재 남은 작업은 인물 세 명인데 설정도 미완료처럼 보인다.

## 현재 자료에서 확인할 수 있는 해결 근거

8개 문서의 CHAR-02·CHAR-03·CHAR-04는 장면별 출연 집합이 동일하며 이름과 ID의 직접 대응이 없다. 임의 배정을 하지 않는 처리는 유지해야 한다.

별도로 이전에 검증한 `02_CHARACTER/characters.json`에는 이름·ID 대응이 있다. 이번에 인물표·footprint·방송 대본 보고서·manifest의 파일 해시와 기존 저장 패키지·설정의 해시가 [보충 검증 기록](../../.local/validation/identity-resolution-20260910.json)과 모두 일치함을 재확인했다.

| 이름 | 확인된 ID |
|---|---|
| 윤서진 | CHAR-02 |
| 백기철 | CHAR-03 |
| 오민주 | CHAR-04 |

기존 연결 완료 패키지는 `.local/prj-007-linked-documents-20260910/storyboard_handoff.json`에 보존돼 있다. 새 문서 검토가 이 패키지나 별도 검증 기록을 자동으로 재사용하지는 않는다.

## 권장 구현 범위와 완료 조건

- 인물별로 보류 이유, 남은 후보, 필요한 증거를 표시하고 **인물 대응표로 보완** 작업을 제공한다. 사용자가 선택한 파일만 지원 어댑터로 읽는다. 임의 상위 폴더 탐색이나 모델의 자유로운 파일 접근으로 해결하지 않는다.
- 서버가 보충 자료의 스키마, 프로젝트와 원본 버전의 연결 근거, 이름·ID의 유일성, 현재 후보, 기존 사용자 결정과 충돌을 검사한다. 근거가 충돌하거나 연결을 증명하지 못하면 해당 항목의 문제를 표시한다.
- Codex는 보완된 근거를 검토하고 설명한다. 명시적인 이름·ID 대응은 코드로 검사하며 모델의 자신감으로 원문 확인 상태를 부여하지 않는다.
- 적용 전 현재 값과 제안 값, 근거를 한 화면에 제시한다. 적용할 때 현재 입력 기준이 그대로인지 다시 확인하고 결과·출처·확인 상태를 패키지에 함께 저장한다. 원본 변경이나 사용자 수정에 오래된 결과를 덮지 않는다.
- 다른 이야기에서도 같은 형식으로 동작해야 한다. 현재 사례의 세 이름이나 CHAR 접두사를 핵심 로직에 고정하지 않는다. 향후에는 8개 문서를 내보내는 쪽에서 이름·ID 대응을 manifest의 지원 버전에 포함하면 추가 자료 없이 완료할 수 있다.

완료 판정은 **미해결 3→0, 이미 확인한 연결·설정 보존, 근거가 포함된 새 패키지 생성과 재읽기, 다른 구조의 독립 스토리 검증**까지다. 자료가 부족한 프로젝트는 필요한 자료를 명시하고 보류한다. 그림·음성 및 최종 콘티 출력 승인은 별도 단계다.
