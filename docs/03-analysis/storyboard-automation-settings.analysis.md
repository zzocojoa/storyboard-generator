# 콘티 자동화 설정과 선행 조건 분석

## 범위와 판정 기준

사용자가 원하는 흐름은 **Codex가 설정·배치·컷·그림·가이드 음성을 포함한 검토용 초안을 만들고, 사용자가 결과를 검토해 필요한 부분만 재생성하는 것**이다. 이 문서는 그 흐름에 필요한 설정과 현재 코드의 공백을 분석한다. 자동 실행기 구현이나 실제 제작 값 적용을 완료했다는 문서가 아니다.

확인 대상은 Schema 1.10.0의 코드와 `의부증의 늪 — draft-01`, 작업 ID `storyboard:7fe9debd-f4a0-4dae-9fdb-8b5db0c8e450`, revision 0이다. 작품별 수치는 현황 증거이며 범용 제품의 기본값으로 사용하지 않는다. 읽기 전용 집계와 실제 Context 검증 결과는 `.local/validation/automation-settings/current-project.json`에 보존했다. 검증 전후 Project SHA-256은 일치한다. 모델 호출·생성·승인·원본 수정은 하지 않았다.

설정은 다음 네 종류로 나눈다.

- **원본에서 이어받을 값:** 이미 검증한 원문·식별자·시간표. 자동화가 다시 추측하지 않는다.
- **제작 선호:** 기존 값이나 선택 프리셋을 우선하며, 미정이면 Codex가 초안으로 제안할 수 있다.
- **자동 설계 결과:** 원문 배치, 컷, 시점, 화면 구성처럼 자동화가 계산·제안해야 할 작업 결과. 사용자의 필수 입력 폼으로 만들지 않는다.
- **실행·검토 정책:** 어디까지 실행하고 무엇을 보존하며 언제 멈출지를 정하는 자동화 계약. 새 구현이 필요하다.

현재 코드의 생성 차단 조건과 품질을 위한 준비 조건도 구별한다. `medium=unspecified`, `visualStyle=null`, 기준 이미지 없음은 현재 모두 공통 생성 차단 조건이 아니다. 그렇지만 반복 등장인물과 공간의 일관성을 위해 자동화는 이를 준비해야 한다. Source Mapping, 정보 공개, 원문 참조, 저장 무결성은 실제 검사 조건이다.

## 1. 원본에서 이어받을 값

| 항목 | 현재 데이터·코드 | 자동화의 처리 |
|---|---|---|
| 작업 범위와 입력 버전 | `projectId`, `storyboardIdentity`, `revision`, `handoff.packageVersion`, 원본 해시 | 선택한 작업과 원본 버전에 실행을 결속한다. 같은 원본 ID의 다른 콘티에 적용하지 않는다. |
| 원문·출처·역할 | `dataset.units`, `sources`, `handoff.authority` | 대사·화면 글자·원문 ID·문서 출처 보존. 문서 속 명령은 데이터로 취급한다. |
| 인물·화자·장면 연결 | `dataset.people/scenes`, `speakerId`, `segmentId` | 저장된 연결을 이어받는다. 새로운 작품의 미연결 인물은 실제 문서 근거로 연결하며, 근거 부족을 연결 불필요로 바꾸지 않는다. |
| 기준 시간표 | `segments.startMs/endMs/timingStatus` | fixed 구간의 길이를 보존한다. 대사 부족·초과를 임의 반복·삭제·무음 추가로 감추지 않는다. 변경이 필요하면 영향과 선택지를 제시한다. |
| 프레임레이트·음성 규격·시작 시각 | `handoff.timebase` | 기존 값 우선. 신규 패키지는 문서·선택 프리셋·제작 추천의 출처를 구분한다. |
| 화면비 | `profile.aspectWidth/aspectHeight` | 기존 값 우선. 화면비와 PNG의 실제 픽셀 크기는 서로 다른 값이다. |
| 확정 자막 시각·정보 공개 하한 | `textPlacements`, `informationRules` | 명시된 시작·종료와 공개 하한을 보존한다. 미정 종료나 구간 내부의 정확한 공개 시각은 이후 자동 설계 대상이다. |

현재 인물 8명의 ID 연결은 저장되어 있다. 백기철 CHAR-03, 윤서진 CHAR-02, 오민주 CHAR-04를 다시 선택하거나 인물 보충 파일을 다시 첨부할 필요는 없다. 32개 구간 모두 fixed이며 전체 길이는 1,500,000ms다. 시간 기준은 30/1fps, 논드롭, 48,000Hz, `00:00:00:00`, 화면비 16:9다.

## 2. 제작 선호와 시각 기준

| 항목 | 정확히 정할 내용 | 현재 지원·누락 | 결정 주체 |
|---|---|---|---|
| 영상 제작 방식 | 실사·AI·혼합 중 제작 의도 | `Profile.medium` 지원, 현재 미정 | 기존 값·프리셋 우선, 없으면 Codex 추천 초안 |
| 콘티 그림 스타일 | 선화/채색, 사실성, 명암·색감, 화면 표현의 구체적 지시 | `Profile.visualStyle` 자유 문자열, 현재 null | Codex가 문서의 연출 의도와 선호로 초안 작성 |
| 인물 시각 기준 | 외형·헤어·의상, 장면별 변화, 같은 인물의 식별 특징 | 원본 `Person.visualDescription`와 character Asset 지원. 현재 외형 설명 0/8, 기준 Asset 0 | 원문 특징 보존 + 부족한 외형을 제작 초안으로 설계하고 기준 이미지 생성 |
| 공간·소품 기준 | 장소 배치·방향·조명, 반복 소품의 형태와 상태 | Location·reference Asset·continuity 지원. 현재 원문 장소 2개, 컷의 장소 지정 0/32 | 기존 원문 장소를 연결하고 실제 화면에 필요한 자원만 제안 |
| 구간 유형별 화면 방식 | 내레이션에 어떤 화면을 유지할지, 패널을 화면에 등장시킬지, 손·실루엣·음성 출연 구분 | `Presence`, `visualMode`, 장소 연결은 있음. 별도 패널/내레이션 제작 프리셋은 없음 | 작품별 설정과 원문으로 Codex 설계 |
| 그림 자산 사양 | 필요한 프레임 수, 기준 이미지 참조, 저장 형식, 실제 크기·화면비 검증 | PNG 생성·크기 검사·해시·대상 연결 존재. 픽셀 크기·품질·개수 제한을 묶은 자동 실행 설정은 없음 | 제품의 지원 범위 안에서 실행 정책과 Codex 계획으로 관리 |

`medium`은 완성 영상의 제작 방식이고 `visualStyle`은 콘티 그림의 표현이다. 콘티를 AI로 그린다고 영상 제작 방식까지 무조건 `ai`로 설정하지 않는다. 현재 원본 인물·장소 설명과 별개로 **자동 설계한 외형·세트의 출처, 버전, 사용자 수정 보존**을 기록할 제작 기준이 필요하다.

기준 이미지가 없다는 이유로 사용자가 항상 이미지를 첨부해야 하는 것은 아니다. 자동화는 원문과 제작 선호로 기준 이미지를 생성한 뒤 각 프레임에서 재사용할 수 있어야 한다. 원문에 없는 인물의 정체나 사건을 만들어 내는 것과 시각적 제작 제안을 구별한다. 손·음성만 등장하는 인물까지 모든 종류의 기준 자산을 강제로 만들지 않는다.

현재 `currentVisualReferenceAssets`는 인물/장소의 최신 자산 버전을 선택한다. 자동 실행 도중 새 기준 이미지가 등록되면 입력이 달라질 수 있으므로 실행별 참조 ID·해시·버전을 고정하거나 변경 시 영향을 받는 작업을 무효화해야 한다. 새로운 세트는 원본 Dataset을 덮어쓰는 방식이 아니라 제작 자원으로 표현할 계약이 필요하다.

## 3. Codex가 자동으로 설계해야 할 값

| 분야 | 자동 설계의 산출값 | 반드시 보존·검사할 조건 |
|---|---|---|
| 원문 배치 | Unit별 `primary-visual / continued-visual / audio-only / context-only`, 대상 컷 | 원문 누락·미지 ID 금지, SOUND/MUSIC의 직접 시각 원문 오용 금지, 반복 연결과 대사 중복 재생 구분 |
| 공개 시점·표시 구간 | Unit 최초 공개, 직접 시각 원문의 시작/끝, 장면 간 공개 순서 | 공개 증거 점과 실제 화면 표시 길이 구분, 정보 하한·원문 순서 보존, sourced 화면 공백 검사 |
| 컷 설계 | 컷 수·길이, 행동, 구도·앵글·이동, 화면 등장과 장소 | 고정 구간 길이 합계 보존. 현재 32컷은 구간당 1컷 뼈대이며 목표 컷 수가 아님 |
| 프레임 설계 | 시작/키/끝 프레임과 offset, 프레임별 묘사 | 해당 프레임 시각에 허용된 원문과 인물·상태만 사용 |
| 전환·연속성 | 전환 종류·길이·다음 화면 노출 시점, 시선·축·소품 전후 상태 | 전환으로 미래 정보를 먼저 노출하지 않음. Black/Hold를 오류를 숨기는 수단으로 사용하지 않음 |
| 글자 연결 | 정확 일치·축약·대체·별도 요소·독립 문구 중 관계와 근거 | Canonical 원문과 실제 표시 문구 각각 보존, 무관한 원문에 강제 연결하지 않음 |
| 독립 글자의 정보성 | 정보성 여부, 해당하는 Information ID, 공개 시점 | 독립 문구라고 자동으로 비정보성으로 확정하지 않음 |
| 글자 표시 | 시작/끝, overlay/prop-text/dialogue-subtitle, 가독성·화면 내 위치 | 원본 확정 시작 보존, 미정 종료는 초안. 글자 위치·서체·크기·줄바꿈 등은 현재 Cue Schema의 독립 필드가 아니므로 표현 정책 확장이 필요 |
| 음성·음향 배치 | 발화 순서·시작, 측정 길이, J/L컷 사용 여부, 효과음 큐 | 실제 낭독 원문 보존, 발화 반복 없음, 인접 구간·정보 공개·대화의 겹침 의도 검사 |

현행 Schema는 Source Link에 `confirmed / mapping-required`, Anchor에 `confirmed / review-required`를 사용한다. Proposal이 만든 Anchor에도 `basis=proposal`, `status=confirmed`를 쓴다. 따라서 `confirmed`를 일괄적으로 사람의 승인이라고 해석하거나, 기존 상태를 일괄 변경하여 자동화 완료로 처리해서는 안 된다. **제작 초안이 구조 검사를 통과한 상태와 사용자가 결과를 승인한 상태를 별도 축으로 정의**해야 한다. Shot 승인과 Frame 검토는 이미 별도 상태가 있지만 제작 설정·Text Mapping·공개 계획의 자동 결정 이력은 충분하지 않다.

자동 설계 항목에는 최소한 대상 필드·제안 값·원문 근거·추론 이유·입력 revision/해시·작성 주체·사용자 수정 여부·후속 검토 상태가 필요하다. 이는 새 계약 제안이며 현재 공통 스키마에 모두 존재하는 필드가 아니다.

## 4. 음성·효과음과 처리 순서

### 현재 가능한 것

- 설정된 음성은 `codex.speechVoice=Yuna`이고 `/usr/bin/say` 목록에서 ko_KR Yuna를 확인했다. `say`와 `afconvert` 실행 파일도 존재한다.
- 가이드 음성 생성 대상은 dialogue·voiceover·panel이다. 프로젝트의 sampleRate를 이용해 PCM WAV로 변환하고 실제 길이·코덱·채널을 검사한다.
- 현재 프로젝트는 발화 60개(대사 32·내레이션 12·패널 16), SFX 3개이며 실제 등록 음성은 0개다.
- 현재 voice는 앱 설정 한 곳에 있다. 인물별 voice·속도·감정 프리셋을 선택하는 Project 설정은 없다. 초기 자동화에서 인물별 연기 음성이 지원된다고 표시해서는 안 된다.
- 발화 언어와 합성 음성의 언어도 일치해야 한다. 현재 Speech 안내는 한국어이고 설정 음성은 ko_KR이다. 다른 언어의 원문은 지원 음성을 확인하는 별도 설정이 필요하며, 한국어 음성으로 모든 언어를 지원한다고 간주하거나 원문을 자동 번역하지 않는다.
- SFX/MUSIC는 가이드 발화 합성 대상이 아니다. WAV 등록 경로는 있지만 자동 음원 선택/생성 서비스와 사용 가능한 음원 라이브러리 계약은 없다. 현재 음악 Cue는 0개지만 원문에는 음악 지시가 있다. 지시 개수를 재생 가능한 음악 트랙 수로 해석하지 않는다.

### 새로 정할 정책

1. 기본 산출물은 **그림과 가이드 발화가 있는 검토용 콘티**로 구분한다. SFX/MUSIC는 원문 제작 지시를 보존하고, 실제 음원이 필요할 경우 제공 파일/명시적으로 선택한 자산/새로 지원할 생성 경로를 정한다. 미등록을 완료나 무음으로 간주하지 않는다.
2. 음성 원문을 출력용 타임라인과 분리된 staging에서 합성·측정한 뒤, 그 길이로 발화 시점·컷 계획을 검증하는 흐름이 필요하다. staging 음성을 검증된 출력 Asset으로 먼저 등록하지 않는다.
3. 측정 음성·예정 Source Anchor·자막을 함께 넣은 후보 타임라인의 공개 순서와 하한을 검사하고, 통과한 결과를 기존 revision/Asset 트랜잭션 계약으로 등록한다.
4. 낭독 길이가 고정 구간에 맞지 않으면 우선 구간 내부 배치를 수정한다. 원문 삭제·반복·임의 시간표 변경으로 해결하지 않는다. 그래도 불가능하면 해당 구간의 선택지와 영향을 제시한다.

이 순서가 필요한 이유는 `requireSpeechContext`가 정보 공개 검토 완료를 요구하고, `effectiveInformationGate`는 audio-only 정보의 근거로 이미 등록·측정된 Audio를 사용하기 때문이다. `attachAudioAsset`도 변경 전 Project에서 Gate를 검사한다. 현재 `SEG-001/audio-5`의 Context를 읽기 전용으로 계산하면 `AUDIO_OUTPUT_GATE_BLOCKED`가 발생한다. 따라서 음성 설정 한 칸을 채우는 것으로 해결되지 않는 의존 순환이 있다.

| 출력 위치·버전 | 실행 기록·임시 미디어·최종 결과 저장 위치 | 선택 프로젝트 출력 영역, 기존 Asset·Version 보존, 새 파일/버전으로 게시 |

현재 Request는 proposal·image·speech 세 종류 및 pending·applying·completed·failed·superseded 상태를 지원한다. 개별 요청의 중복 방지와 결과 적용 복구는 이미 존재한다. **프로젝트 전체 실행 ID, 단계 순서, 단계별 진척·취소·재개, 자동 계획과 보정, 예산·작업량 상한을 관리하는 실행기는 없다.** Audio Worker의 2개 Worker/4개 대기 한도는 WAV 변환용이며 생성 작업 병렬도나 전체 자동화 한도가 아니다.

현재 비용 API가 없으므로 금액 한도를 정확히 집행할 수 있다고 약속할 수 없다. 실행 횟수·이미지 수·처리 시간을 측정 가능한 한도로 사용하고, 비용은 미측정으로 표시해야 한다. 이미지 도구가 지원하지 않는 픽셀 크기·품질·모델 선택 옵션도 설정 항목만 만들어 제공할 수 없다.

Final 검사 489개는 동일한 원인의 컷·프레임·음성·출력 검사 결과가 겹친 수치다. 원문 연결 검토 45개와 최종 Issue의 `SOURCE_MAPPING_REQUIRED` 32개도 집계 단위가 다르다. 이 수치를 사용자가 489번 수동 입력해야 한다는 의미로 표시하지 않는다.

정보 규칙 95개는 모두 `unit-order`이며 문서 Unit별로 부여된 `document-information:…` 식별자다. 원본의 fact/clue 의미 체계를 복원한 95개 사실이라고 해석하지 않는다. 자동 설계에서 의미상 같은 정보나 반전 노출을 분석할 때는 문서 근거를 기록하고, Unit별 시간 검사만 통과한 것을 이야기의 모든 비노출 조건까지 확인한 결과로 보고하지 않는다.

실패한 첫 구간의 핵심은 다음과 같다.

- `document-unit-39`: 노트북·영수증 행동의 화면 배치와 지속 구간.
- `document-unit-44`: 채팅의 등장 시점과 글자 트랙. 자동 낭독 대상으로 바꾸지 않는다.
- `document-unit-47`: 서진 대사의 발화 시점과 실제 가이드 길이.
- `document-unit-50`: 엘리베이터·발소리의 효과음 시점과 음원.
- `document-unit-52`: 현관 시선·인물 이동·의자의 화면 배치.

이 항목들은 현재 인물 ID 누락 때문이 아니다. 첫 구간의 0ms 고지와 8,000ms 화면 글자는 이미 근거가 있으며, 나머지 배치와 정확한 시각이 자동 설계 대상이다. 이번 분석에서 임의 시간을 선택하거나 검토 상태를 바꾸지 않았다.

## 8. 설정만으로 해결되지 않는 구현 공백과 완료 기준

1. **자동 초안 준비 계약:** 미정 배치와 시각을 입력으로 받아 후보 계획을 만들고, 후보 전체를 검증한 후 적용해야 한다. 기존 `applySegmentProposal`은 이전 컷에 mapping-required가 있으면 적용 전에 거부하므로 스킬 문구 변경만으로 해결되지 않는다.
2. **원본 정보와 제작 제안 분리:** 자동 배치/외형/자막 관계/시각 계획의 출처와 사용자 검토를 보존한다. 실제 원본을 바꾸거나 전체 상태를 confirmed로 바꾸는 해결책을 사용하지 않는다.
3. **음성 측정과 시점 순환 해소:** staging 측정과 후보 타임라인 검증을 도입한다. SAMPLE 길이를 측정값으로 위장하지 않는다.
4. **연속성 계획 전달:** 현재 Proposal 적용은 `continuityBefore/After`를 빈 배열로 만든다. 반복 인물·소품의 상태가 자동 생성에 실제로 전달되도록 별도 계획/적용이 필요하다.
5. **검토 가능한 미디어 화면:** 현재 안전 출력은 accepted가 아닌 Frame bitmap을 차단하며, FrameEditor에는 승인 버튼이 있지만 실제 미승인 원본 그림을 직접 보여 주는 영역이 없다. 무결성을 검사한 검토 전용 그림·재생 경로와 초안 표시를 추가해야 사용자가 결과를 보고 승인할 수 있다. Final 안전 출력과 분리한다.
6. **자동 실행과 선택 재생성:** 단계·의존 관계·진척·한도·중단·재개를 관리한다. 선택 결과를 교체할 때 다른 사용자 수정과 과거 결과를 보존하고 변경 영향만 다시 검사한다.
7. **효과음과 최종 범위:** 현행 Final은 모든 Audio Cue의 재생 가능 여부를 검사하므로 현재 SFX 3개를 실제로 처리하지 않으면 Final은 완료되지 않는다. 검토 초안의 미등록 음향 표시는 허용하더라도 최종 음향 준비와 혼동하지 않는다.

자동화 구현 검증은 원문 배치가 미정인 입력에서 시작해야 한다. 전체 원문 보존, 고정 구간 길이, 그림의 직접 근거, 화면·글자·음성 공개 순서, 실제 가이드 길이, 미승인 결과 열람, 사용자 수정 보존, 선택 재생성·중단 후 재개를 확인한다. 작품 ID·인물·분량이 다른 입력에서도 같은 설정 계약을 적용해야 한다. 이미 모든 연결이 수동 확정된 fixture만으로 자동화 성공을 판정하지 않는다.

이번 단계의 결론은 **기존 값 재사용 → 제작 선호 초안 → 원문·시간·컷 통합 계획 → 음성 측정·계획 보정 → 기준 자산·프레임 생성 → 자동 검사 → 사용자 검토·선택 재생성**이다. 사용자는 제작 선호를 직접 지정할 수 있으나, 원문 배치·시각·컷별 필드를 전부 수동 입력하는 것이 자동화의 시작 조건이 되어서는 안 된다.

## 9. 광역 조사: 추가 설정과 숨은 동작

2026-09-11 기준으로 입력 어댑터·문서 검토, 공통 스키마, Proposal·이미지·음성 경로, 편집·재생 UI, 출력, Build·Request·저장 설정까지 범위를 넓혔다. 아래 **14개는 설정 개수가 아니라 추가·세분 조사 영역**이다. 이미 1~8절에 있는 항목은 세부 공백만 보완한다. 코드가 없는 부분은 설계 제안이며, 현재 사용할 수 있는 옵션으로 표시하지 않는다.

조사는 로컬 소스·설정·저장본의 읽기 전용 확인이다. 실제 모델 호출, 장시간 생성, 브라우저 절전, 외부 배포·공유는 검증하지 않았다. 새 설정의 기본 수치와 모델별 지원 옵션은 이번 분석만으로 확정하지 않는다. 근거 파일 해시와 주요 고정값 검사는 `.local/validation/automation-settings/broad-audit.json`에 남긴다.

**현재 코드에서 드러난 구체적인 차이:**

- 70초 컷에서 1퍼밀은 70ms다. 30fps의 한 프레임 약 33.3ms보다 크다. 밀리초 저장, 퍼밀 제안, 프레임 타임코드 표시는 같은 정밀도가 아니다. 현재 시간표를 다시 반올림하라는 뜻이 아니라 자동 계획의 정밀도 계약을 명확히 해야 한다는 뜻이다.
- 여러 글자 Cue가 동시에 활성화되면 현재 동일한 `.monitor-text` 위치에 렌더링된다. 코드상 배치 충돌 가능성이고, 현재 작품의 모든 자막이 실제로 겹친다는 판정은 아니다. 오버레이와 휴대전화 속 글자도 현재 표현 경로만으로 서로 다른 위치에 자동 조판되지 않는다.
- 임시 글자 유지 시간은 가져오기 UI에서 2000ms이며 `mapping.ts`에도 별도의 2000ms 사용처가 있다. 가져오기 한 곳의 값만 바꿔도 이후 모든 글자 생성·수정에 같은 정책이 적용된다고 볼 수 없다.
- UI에서 CUT 외 전환을 처음 고를 때 `min(500ms, 컷 길이)`를 넣는다. 이는 편집 초기값이며 장르별 최적 전환 길이나 Codex의 제작 판단이 아니다.
- `inspectImageBytes`의 40메가픽셀 상한은 최대 디코딩 부담 제한이다. 실제 필요한 해상도·프로젝트 비율 일치·그림 품질을 보장하는 값이 아니다.

|---|---|---|
| 앱 설정: 음성 | `codex.speechVoice=Yuna` | 앱 전체 가이드 음성. 인물별 설정과 다름 |
| 앱 설정: 문서 검토 timeout | 240000ms, Schema 허용 1000~600000ms | 문서 검토 한 번의 제한. 전체 콘티 실행 시간으로 재사용하지 않음 |
| 앱 설정: 오디오 Worker | 실행 2, 대기 4, 실행·대기 입력 예약량 합계 100MiB | WAV 변환 자원. 이미지/모델 작업 동시성 아님 |
| 앱 설정: 오디오 대기·실행 제한 | 각각 30000ms | 대기 실패와 변환 실패를 구별 |
| 앱 설정: Worker 메모리 | old 96MiB, young 16MiB, stack 4MiB | 운영자가 조정할 처리 자원; 콘티 제작자 필수 입력 아님 |
| 앱 설정: PDF 폰트 | `assets/fonts/NanumGothic-Regular.ttf` | 폰트 파일 경로는 존재하나 언어별 선택·자동 glyph 검사 계약은 별도 |
| 코드 제한: 문서 | 파일당 4MiB, 검토 Prompt 2MiB, 엔진 응답 2MiB | 입력을 읽을 수 있음과 한 번에 모델 검토할 수 있음을 구별 |
| 코드 제한: 이미지 | 20MiB, 40000000픽셀, PNG/JPEG/WebP 검사 | 생성 CLI 이미지 결과는 PNG 경로. 최대 크기를 품질 설정으로 노출하지 않음 |
| 코드 제한: 음원 | 입력·정규화 결과 각각 50MiB, 최대 1시간, 8000~384000Hz 입력, 최대 4096 WAV chunk | 16/24-bit mono/stereo PCM WAV 입력 → 프로젝트 sampleRate의 PCM16. 모든 제한을 동시에 만족해야 함 |
| 코드 제한: Proposal | 구간당 1~64컷, weight 1~10000, 정수 퍼밀 Anchor/Frame | 응답 구조 제한. 목표 편집 리듬과 별도 |
| 코드 초기값: 글자·전환 | 임시 글자 2000ms 사용처, 새 비CUT 전환 최대 500ms | 검토 전 임시값; 자동 제작 정책은 별도로 일관되게 정의 |
| 코드 제한: Request Lock | 대기 5000ms | 저장 경쟁용 대기. 외부 생성 재시도 대기나 전체 작업 timeout 아님 |

음원 예를 들면 48kHz·stereo·PCM16의 25분 파일은 헤더 제외 약 288000000바이트로 50MiB를 넘는다. 따라서 '최대 1시간 지원'만 보고 작품 전체를 WAV 한 개로 만들어 등록하는 전략은 실패할 수 있다. 현재 Cue별 가이드 합성 구조를 활용하고, 전체 믹스 내보내기는 별도 지원 범위로 설계해야 한다. 이 계산은 파일 생성 없이 규격으로 산출했다.

현재 빈 출력 폴더도 `writeDocumentPackage`의 `mkdir`에서 기존 경로로 거부된다. 자동 패키지 저장은 상위 폴더, 새 결과 폴더 이름, 버전 충돌 방식을 구분해 안내해야 한다. 사용자가 만든 빈 폴더를 지원하려면 소유권·부분 생성·기존 파일 처리 계약을 바꾸는 구현이 필요하며, 현행 설정 한 칸을 바꾸면 해결되는 문제가 아니다.

### D. 설정으로 노출하지 않을 조건

- **검증 우회:** Source·Information Gate·Asset 무결성·Final 검사 생략은 자동화 설정으로 제공하지 않는다. 필요한 후보 계획을 생성·검증하는 경로를 추가한다.
- **후보 점수에 의한 자동 확정:** Text 후보 유사도 0.35 같은 내부 점수는 후보 검색용이다. 점수를 낮추어 문구 관계를 확정하는 기능으로 바꾸지 않는다. 인물 ID도 이름과 ID의 근거가 필요하며, Text 후보 점수와는 별개의 판정이다.
- **자동 최종 승인:** 기술 검사 통과를 사용자의 그림 승인으로 간주하지 않는다. 정상 생성 이후의 연출·그림 재생성은 사용자가 결과를 보고 결정한다.
- **원본 변경 허용의 묵시적 확장:** 낭독을 맞추기 위한 대사 재작성·반복, 원본 시간표 변경, 존재하지 않는 등장인물 생성은 빈칸 자동 채우기에 포함하지 않는다.
- **저장 보호 제거:** 해시·CAS·lock·journal·경로 검증과 과거 Record 보존을 속도 설정으로 약화하지 않는다.
- **제공되지 않는 옵션:** 현재 이미지 도구가 보장하지 않는 모델·seed·품질 파라미터를 지원 기능처럼 만들지 않는다. 정확한 비용이 제공되지 않으면 금액 한도가 아닌 작업 수·시간 한도를 사용한다.

## 10. 광역 조사에 따른 구현 우선순위

| 우선순위 | 먼저 계약으로 정할 내용 | 완료를 확인할 방법 |
|---|---|---|
| P0: 자동 초안이 끝까지 이어짐 | 8절의 자동 계획·staging 음성·검토 전용 미디어·실행기를 중심으로, B01 시간 정밀도, B06 전후 상태, B07 생성 대상/완료 기준, B08 최종 설정 Snapshot, B09 입력 분할, B10 실행 능력, B11 수정 보존, B14 단계 한도·저장 공간 처리를 결합 | 미정 배치에서 전체 초안 생성, 실제 생성 수·측정 음성·정확한 상태 표시, 중단/재개·선택 재생성. 문서 수가 같고 내용·길이가 다른 작품에서도 동작 |
| P1: 사용자가 제대로 보고 판단함 | B02 표현 밀도, B03 비율·여백 일치, B04 글자 가독성/겹침·PDF 합성, B05 기본 음량/발화 검토, B12 긴 내용 누락 없는 PDF, B13 목적별 전달물 | 이미지 비율 불일치·긴 대사·동시 글자·반복 인물·음성 겹침·세로형 화면의 검토 결과가 화면과 출력에서 일치 |
| 후속: 지원 범위 확장 | 고급 믹싱·음원 라이브러리, 다국어 발음 사전, 다양한 인쇄 템플릿, 전체 오디오/영상 렌더링·외부 편집기 포맷 | 별도 요구가 생긴 기능부터 지원 계약과 실제 제공 능력을 검증. 자동 초안 기능을 모든 기능 확장 완료까지 미루지 않음 |

P0/P1은 구현 순서이며 사용자가 수동으로 입력해야 하는 항목 수가 아니다. 내부 제한값을 모두 설정 화면에 옮기지 않는다. 초기 UI는 **기존 설정으로 자동 초안 만들기**를 중심으로 하고, 필요하면 제작 프리셋·그림 표현 수준·지원 가이드 음성·결과 형식·실행 범위를 펼쳐 수정하도록 설계한다. 비어 있는 제작 선호는 Codex가 이유와 함께 제안하고 실행 계획에 기록한다. 자동 계획이 도출할 원문 Anchor·컷 길이·등장 모드·자막 종료를 사람의 선행 입력으로 되돌리지 않는다.

실행 전에는 적용할 제작 기준, 예상 컷/그림/발화 수, 보존할 사용자 수정, 실제 지원하지 않는 작업만 짧게 보여 준다. 자동화가 기술적으로 끝나면 완료 결과와 남은 예외를 제공하고, 사용자는 같은 화면에서 비교·승인·선택 재생성을 진행한다. 완료 수에는 정상 부재/생성 제외를 별도로 표시하고 실패를 성공으로 합산하지 않는다.

## 11. 설정을 바꿨을 때 다시 계산할 범위

자동화 설정은 저장하는 것만으로 끝나지 않는다. 변경이 어떤 생성 결과와 검토 상태에 영향을 주는지 명시해야 부분 재생성이 가능하다. 아래는 새 자동화의 설계 기준이며 현행 전체 실행기가 구현되어 있다는 의미가 아니다.

| 변경 | 다시 계산할 범위 | 보존할 대상 |
|---|---|---|
| 인물·공간·소품 기준/그림 스타일 | 참조하는 컷의 그림, 연속성 상태, 필요한 시각 검토. 화면비 변경은 글자 조판과 출력도 검사 | 원본 대사·ID·이전 이미지·확정 사용자 연출 |
| 가이드 음성·낭독 속도 | 해당 발화 재합성·측정, 배치·공개 시점·관련 컷/글자 검증. 실제 계획이 달라진 그림만 재생성 후보 | 무관한 인물의 음성·이미지 |
| 글자 서체·크기·여백 | 글자 조판·가독성·겹침·합성 출력 | 글자를 별도 합성하는 경우 배경 그림 Asset과 원문 |
| 글자 시작/종료·원문 연결 | 정보 공개·Source Coverage·해당 시점의 그림/음성 출력 판정. 필요하면 계획을 재검토 | 무관한 구간의 결과 |
| PDF 용지·카드 수·표시 항목 | PDF Projection과 페이지 분할·잘림 검사 | 컷 설계·이미지·WAV·승인 이력 |
| 동시 작업 수·대기 timeout | 실행 스케줄·재시도 가능 여부 | 의미상 입력이 같은 완료 결과. 운영 자원 변경만으로 전체 재생성하지 않음 |
| 원본 패키지/revision·사용자 편집 | 기존 Source Update 영향 분석과 실행 Snapshot을 대조하여 해당 작업의 적용을 재검증 | 사용자 변경과 과거 결과. 오래된 모델 응답으로 최신 편집을 덮지 않음 |

설정 출처는 생성 결과의 입력 결속에 포함하되 운영 경로·비밀·호스트 정보와 구별한다. 새 설정의 영향 범위를 테스트로 명시하고 기존 Request/Project 트랜잭션을 재사용한다. 모든 설정 변경을 전체 재생성으로 처리하거나, 반대로 달라진 설정을 이전 결과와 동일한 요청으로 처리하지 않는다.
